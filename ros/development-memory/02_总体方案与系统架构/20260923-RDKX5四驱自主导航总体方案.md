# 2026-09-23 RDK X5 四驱自主导航总体方案

## 1. 产品目标

基于已经打通的四驱底盘、Retroid 掌机、MQTT、ESP32-C3 和 STM32，新增 RDK X5 作为 ROS2 高层计算平台，实现：

- 手动遥控与人工接管；
- 遥控局部避障；
- 二维激光 SLAM 建图；
- 地图定位和定点导航；
- 动态/静态障碍物绕行；
- 多航点巡逻、失败重试和任务状态；
- 失联、倾倒、堵转和紧急停车保护；
- 后续扩展摄像头识别、目标跟随和低矮障碍物感知。

### 1.1 用户确认的最终功能边界（2026-09-23）

最终车辆必须同时保留并支持三条控制链路：

1. 掌机蓝牙直接控制；
2. 掌机 MQTT 远程控制；
3. 新增 RDK X5 ROS 控制。

原有蓝牙和 MQTT 链路、指令语义、STM32 本地避障及原自主模式保持兼容，不删除、不重写、不改变原有使用方式。新增 ROS 控制提供四项能力：自主导航、导航避障、路径规划、定点/多航点巡逻。

“原 STM32 自主模式”和“ROS 地图自主导航”必须在协议、状态和界面命名上分开，避免操作者误判当前控制源。

## 2. 职责分层

### STM32 实时安全层

- 采集 ICM42670、四路编码器、电池和本地雷达安全距离。
- 运行四轮速度闭环和差速运动解算。
- 接收 RDK 的连续速度目标。
- 保持本地急停、失联停车、倾倒和避障保护。
- 向 RDK 输出带序号、时间戳和校验的底盘遥测。

### RDK X5 ROS2 决策层

- 接收 LD14 完整 360°扫描并发布 `/scan`。
- 通过底盘驱动发布轮速、IMU、电池和状态话题。
- 融合轮速与 IMU，生成连续里程计。
- 运行 SLAM、AMCL、Nav2 和航点巡逻。
- 提供地图、路径、任务和诊断数据给掌机或 Web 控制台。

### 掌机/MQTT 人机与远程层

- 手动遥控、模式选择、急停和人工接管。
- 展示车辆在线、地图定位、导航目标、巡逻进度和故障。
- 不与 Nav2 同时直接控制电机；控制权必须互斥。

### Windows网页控制台与交付层（2026-09-23新增优先级）

- RDK X5建立Wi-Fi热点，Windows笔记本连接后通过固定IP网址进入控制台。
- 电脑网页优先打通并作为SLAM、定位、导航、避障、路径规划和巡逻的主验收界面。
- 实时显示地图、车辆位姿、雷达、全局/局部路径、障碍物、速度、电池、控制源、任务状态和故障。
- 支持人工遥控、模式切换、地图建图/保存、初始位姿、地图选点导航、取消、急停、航点编辑和巡逻控制。
- 网页命令经RDK受控ROS网关进入Nav2或ROS速度仲裁，再经UART5和STM32安全层驱动车辆。
- 客户交付版离线可用、开机自启、具有登录权限与操作审计；不向浏览器开放通用ROS超级权限。
- Windows网页完整验收后，再把同一响应式页面/PWA集成到掌机，不重复开发第二套导航前端。

#### Bee ROS Web Console 最终UI信息架构

- 顶栏：Bee ROS Web Console、车辆名称、RDK/STM32/LD14/ICM42670在线状态、Wi-Fi信号、当前控制源、ROS模式和急停。
- 主地图：地图、车辆位姿、LD14扫描、全局/局部路径、目标点、巡逻航点、障碍/代价区域和比例尺。
- 地图工具：初始位姿、发送目标、清除目标、添加/编辑/排序航点、保存任务。
- 任务面板：自主导航、导航避障、路径规划、定点/多航点巡逻四项能力的状态、进度、暂停、恢复、重试、取消和失败原因。
- 遥测面板：线速度、角速度、四轮速度、电池、定位质量、雷达频率、控制延迟和最近故障。
- 常驻安全区：网页人工接管按住运动/松开归零、控制源切换提示、取消任务和急停。
- 响应式布局：Windows桌面优先；窄屏地图保持主视图，任务/遥测面板改为抽屉，急停和控制源永远可见。
- 状态覆盖：连接中、在线、断开、ROS未启动、地图未加载、定位丢失、导航执行、暂停、失败、急停和人工接管。
- 视觉规范：深色工业控制台；蓝灰中性底；青绿色表示正常/导航；橙色表示警告；红色只表示急停/危险；地图最大化，少卡片、高信息密度、无营销式装饰。
- UI实现策略：先完成静态整体UI和响应式交互，再按“只读状态→地图/雷达→目标导航→巡逻→人工控制→交付安全”顺序接入真实ROS。

## 2.1 三条控制链路与回归保护

```text
掌机蓝牙 --------> 蓝牙模块 -> STM32 USART2 --┐
掌机 MQTT -> Broker -> ESP32-C3 -> STM32 UART4 ├-> 控制源仲裁 -> 原安全保护 -> 四轮电机
RDK X5 ROS2 --------------------> STM32 UART5 --┘
```

- USART2 和 UART4 的现有协议与行为是保护基线，ROS 接入不得修改其对外兼容性。
- UART5 ROS 控制采用新增正式二进制协议和连续速度，不复用 A-H 离散指令冒充 Nav2。
- 控制优先级固定为：硬件急停 > STM32安全保护 > 人工蓝牙/MQTT > ROS自主。
- 蓝牙与 MQTT 之间的现有仲裁方式以源码审计和实测为准；在取得证据前不擅自改变。
- 任一控制源切换前先输出零速度、清除旧命令并刷新超时计时，避免残留动作。

## 3. 数据链路

```text
LD14 TX ──┬──> STM32 USART1：本地近障与安全停车
          └──> RDK USB-UART/独立UART：完整扫描 -> /scan

ICM42670 -> STM32 -> UART5 IMU帧 -> bee_base_driver -> /imu/data_raw
四编码器 -> STM32 -> UART5轮速帧 -> bee_base_driver -> /wheel_ticks

/wheel_ticks + /imu/data_raw -> robot_localization -> /odometry/filtered
/scan + TF + /odometry/filtered -> SLAM/AMCL/Nav2
Nav2 /cmd_vel -> bee_base_driver -> UART5速度帧 -> STM32四轮PID
```

## 4. ROS2 话题与 TF 方向

计划核心话题（Topic，连续数据流）：

- `/scan`
- `/cmd_vel`
- `/wheel_ticks`
- `/imu/data_raw`
- `/battery_state`
- `/chassis/status`
- `/odometry/filtered`
- `/tf`
- `/tf_static`

计划核心动作（Action，长时间任务，包含目标、反馈和结果）：

- `/navigate_to_pose`，类型 `nav2_msgs/action/NavigateToPose`
- `/follow_waypoints`，类型 `nav2_msgs/action/FollowWaypoints`

计划 TF：

```text
map -> odom -> base_link -> laser_link
                         -> imu_link
```

## 5. 底盘控制原则

- Nav2 必须下发连续 `linear.x` 和 `angular.z`，不得只映射成 A-H 八方向动作。
- 四轮差速目标：左侧速度 `v - w*track/2`，右侧速度 `v + w*track/2`。
- STM32 按四路编码器分别闭环，ROS 不直接发送 PWM。
- 手动、辅助避障和 ROS 自主三种控制源互斥；切换前先停车并清空旧命令。
- 优先级：硬件急停 > STM32 安全保护 > 人工接管 > ROS 自主。

## 6. 传感器原则

- RDK 必须取得 LD14 完整扫描，四向距离不足以完成 SLAM。
- 雷达 TX 可在电平和驱动能力确认后分接两个高阻 RX；禁止两个 TX 并接。
- ICM42670 为六轴 IMU，没有磁力计；Yaw 单独积分会漂移，必须依赖轮速和激光定位修正。
- 所有传感器数据应携带采样时刻，不得用 Linux 收到数据的时刻替代 STM32 采样时刻。
- 二维雷达看不到过低或过高障碍物，后期可增加保险杠、超声波或深度相机。

## 7. 分阶段路线

0. 原功能基线冻结：分别实测掌机蓝牙、掌机 MQTT、STM32 原避障/自主模式和失联停车，形成回归清单。
1. 协议与仲裁定稿：控制权、连续速度、轮速、IMU、电池、状态、时间戳、序号、CRC和旧协议兼容策略。
2. STM32 增量版本：从 `1-28` 派生新目录，合并 ICM42670，新增 UART5 正式帧、四轮速度闭环和控制源仲裁；随后完整回归旧链路。
3. RDK 底盘驱动：实现 `bee_base_driver`，先完成板对板安全收发、超时停车、人工抢占和状态回传。
3A. Windows网页原型：部署Vizanti ROS2验证热点访问、地图/雷达/位姿、目标点和航点交互；同步建立自有网页和受控ROS网关骨架。
4. 雷达与标定：打通 LD14 完整 `/scan`，标定轮径、轮距、编码器、方向、速度 PID、IMU零偏和安装位姿。
5. 连续里程计：融合轮速与 IMU，验证定距直线、原地定角和闭环轨迹。
6. SLAM建图与保存：使用原蓝牙或 MQTT 人工低速遥控覆盖目标区域，LD14完整扫描结合轮速/IMU里程计与TF逐步更新占据栅格；验证尺度、回环和墙体重影。经人工检查后，通过网页保存地图文件及元数据、记录版本和对应场地，不把“驶过”误认为“雷达已观测且可通行”。
7. 地图复用、定位与路径规划：重启后加载已保存地图，完成地图选择和AMCL定位，再启用全局规划器和局部控制器。没有有效地图或定位丢失时禁止开始地图导航。
8. ROS 自主导航与避障：先空旷到点，再验证静态/动态障碍物、窄通道、恢复、急停和人工接管。
9. 定点巡逻：实现单点、多航点、循环、失败重试、暂停/恢复和低电量策略。
10. 客户交付与掌机整合：先完成Windows固定网址控制台、离线部署、安全、开机自启和全功能验收；最后将同一响应式控制台集成到掌机，不得破坏原蓝牙/MQTT控制。

## 8. 阶段完成判据

- 每层必须独立验收，不能用上层现象代替底层证据。
- 串口层：CRC、序号、频率、丢帧、超时停车。
- 传感器层：单位、坐标轴、时间戳、静态噪声、动态方向。
- 里程计层：固定距离和固定角度误差统计。
- SLAM层：闭环、墙体重影、地图尺度。
- 地图持久化层：网页保存成功后确认地图文件和元数据存在；重启服务后能选择并加载同一版本，栅格尺度/原点/障碍与保存前一致；完成定位后才允许发起导航。
- Nav2层：到点误差、避障、恢复、失联和人工接管。
- 巡逻层：连续多轮稳定运行和异常恢复。

方案已经获得用户确认，后续以此文件作为实施方向。具体协议参数和硬件标定值必须通过代码与实车证据定稿，不得从示例值直接推断。

## 10. 客户端入口与正式部署基线

- 正式客户端名称固定为 `Bee ROS Web Console`，当前确认UI作为后续前端唯一设计基线。
- 第一交付入口固定为Windows笔记本：连接RDK X5车载Wi-Fi热点，打开固定IP根网址即可进入控制台；掌机复用安排在Windows版完整验收之后。
- RDK X5本机承担Wi-Fi AP、Nginx静态资源、受控Web网关、ROS2/TROS、SLAM、定位、Nav2和巡逻任务；STM32仍承担底层实时控制和最终安全保护。
- 正式网页资源必须离线本地化，不能依赖公网CDN；通用rosbridge只用于隔离开发验证，不作为客户版裸露接口。
- 当前UI样稿仅表示布局和交互契约。正式前端应在项目工程内实现，不直接部署可视化工具生成的iframe包装页。

## 11. 用户确认的建图与复用语义（2026-09-23）

- 车移动到新区域时，只有LD14实际有效观测并被SLAM关联到地图坐标的单元才逐步由未知变成空闲或占据；已经观测的格子在建图过程中仍可被重复观测和回环修正。格子固定的是地图坐标及分辨率，不能把颜色判断理解为一经出现永久不变。
- 建图完成须由网页触发保存，保存经过检查的占据栅格和地图元数据到RDK X5持久存储，提供名称/版本、加载和备份入口。未经明确保存的临时建图结果不得作为下次启动必然存在的地图。
- 后续导航/巡逻先加载指定地图、完成定位，再以静态栅格作全局规划基础，以实时LD14扫描和Nav2局部/全局代价地图处理新增或移动的障碍；静态地图变化需重新建图、更新或审核新版本，不能把临时障碍永久写死到交付地图。
- 网页分清建图中地图、已保存地图、当前加载版本与实时障碍图层；绿格仅表示雷达估计空闲，通行判定还需考虑车体尺寸、膨胀、安全策略以及二维雷达盲区。
- 以上是需求和实施方案，目前没有RDK实机地图保存、重启加载或导航证据，状态为待开发/待实测。
