## 2. STM32 软件基线

当前推荐起点：`1-28 UART5接入鲁班猫ROS底盘协议`。

已具备：

- USART2 蓝牙、UART4 ESP32-C3、UART5 ROS 三条独立链路。
- UART5 接收中断只写 128 字节环形缓冲，主循环统一解析。
- 旧单字节方向、模式、调速、鸣笛、灯效命令。
- `0x51` 雷达/车辆状态、`0x52` 四轮增量/预留陀螺、`0x53` 电池遥测。
- 运动命令约 350ms 超时停车。
- Keil ARMCC 编译 0 Error、0 Warning。
- 当前最大构建记录：Total ROM约21.05KB、Total RW约4.68KB；相对F103RCT6的256KB Flash与48KB SRAM有充足静态容量余量。

尚不满足 ROS 导航的部分：

- 下行是八方向离散动作，不是连续 `linear.x/angular.z`。
- 四轮数据是 10ms 窗口 `int8` 编码器增量，缺少累计值、量程、物理标定和统一时间戳。
- IMU 仅有单字节角度预留位，缺少三轴加速度、三轴角速度、温度和采样时间戳。
- UART5 协议缺少统一帧头、长度、版本、类型、序号和 CRC。
- 现有 `0x5D` 是 STM32 内部自主避障逻辑，不等同于 RDK Nav2 自主控制授权。
- 尚未测量合入ICM42670、正式协议和四轮PID后的CPU负载、最坏循环耗时、中断占用、控制周期抖动及串口丢帧；容量判断不等于实时性已验证。

## 3. RDK/ROS 基线

- 建议使用 RDK OS 3.5.0 和 TROS/ROS2 Humble，避免混用旧版 Foxy 命令。
- 官方 AMR 指南已经覆盖激光雷达、IMU、底盘、Nav2、定点导航和多目标调度。
- 本项目首期采用二维 LD14 路线，不强制加入 ToF、双目或视觉 SLAM。
- 计划节点：LD14 驱动、`bee_base_driver`、`robot_localization`、SLAM、AMCL、Nav2、巡逻任务和 rosbridge。
- 2026-09-25已部署LD14正式ROS2服务与Bee受控只读网页网关：`/scan`约6Hz，Windows访问`http://192.168.127.10:8080/`可实时查看实体回波；服务已设置systemd开机启动。
- 2026-09-25网页已具备标准`/map` OccupancyGrid真实渲染能力，绿色/红色/深灰格、原点/分辨率/yaw坐标换算和Transient Local QoS通过测试地图验证；测试服务为static且不自启，尚不等于SLAM实图。

## 4. 已验证与未验证边界

已验证事实：

- Android/MQTT/ESP32/STM32 远程控制和安全停车已有独立项目证据。
- STM32 四路编码器可产生非零脉冲。
- LD14 完整原始帧解析代码存在。
- UART5 ROS 接口代码能够编译。
- ICM42670 驱动和整板自检工程存在。

未验证：

- RDK OS准确产品版本标签仍待从官方版本文件确认；ROS2/TROS Humble已存在。LD14 CP2102 `/dev/LD14`原始帧、ROS `/scan`连续帧、网页实时显示、断链超时和systemd恢复已通过；SLAM/Nav2仍未验证。
- LD14 TX 同时驱动 STM32 RX 与 RDK/USB-TTL RX 的电气稳定性。
- UART5 与 RDK X5 实际双向通信。
- ICM42670 在当前车辆主线固件中的实时采集。
- 轮径、轮距、编码器每圈计数、左右方向和四轮速度 PID。
- ROS 话题频率、时间戳、TF、里程计、建图、定位、Nav2 和巡逻整车闭环。

## 5. 保护边界

- 后续必须在现状上增量开发，禁止覆盖已有 Android 历史改动。
- 未经用户确认，不删除旧 STM32 版本目录；新阶段优先从已验证基线复制派生。
- 烧录前必须确认目标板、下载器和车轮架空状态。
- 整车运动验证必须保持物理急停和安全空间。
