# 灾备脚本权限与备份范围遗漏

- 日期：2026-09-28
- 状态：已闭环

## 现象

- 普通用户运行板端备份脚本时，读取root-only环境文件报`Permission denied`并提前退出。
- 旧脚本只复制地图和LD14质量目录，遗漏巡逻草稿、rosbag、STM32预检、地图恢复、总验收报告以及`bee-time-check.timer`。

## 根因

- 脱敏环境文件和NetworkManager连接属于root权限，脚本没有在入口声明权限要求。
- 备份范围使用了按目录白名单，新增诊断资产后未同步扩展；systemd只匹配`.service`而未匹配`.timer`。

## 修复

- 脚本开头检查EUID，非root时明确报`backup_requires_root`并退出；固定用`sudo -n bash`运行。
- 备份整个受控`data`目录，并用find同时复制`bee-*.service`和`bee-*.timer`。
- systemd运行/启用清单同时覆盖service和timer。

## 验证

- 最新归档外层SHA-256验证通过。
- 解压后337个条目逐文件SHA-256全部通过。
- 归档已回传电脑，电脑端SHA-256与板端清单一致。
- 脱敏配置仍为`REDACTED`，未带出真实凭据。

## 可复用规则

- 需要读取`/etc`或NetworkManager配置的板端备份脚本必须在入口明确root要求，不能运行到一半才因权限失败。
- 项目新增持久化数据子目录或systemd timer后，备份验收必须检查归档内容，而不能只看tar文件生成成功。
