# ICM42670高低字节撕裂与十四字节原子读取

## 问题现象

当16位温度、加速度或陀螺仪字段的高低字节用多个独立I2C事务读取时，传感器可能在两次事务之间刷新。零点符号翻转附近可能把不同采样的高低字节拼在一起，形成约`±256`计数的假尖峰；这不是正常机械振动，也不能靠简单平均从根本上修复。

## 已验证根因与正确方案

- FY101S最终修订版已验证使用从`TEMP_DATA1 (0x09)`开始的单事务14字节突发读。
- 帧布局固定为温度2字节、加速度XYZ 6字节、陀螺XYZ 6字节。
- 主机对前13字节发送ACK，对最后1字节发送NACK，再发送STOP。
- 地址或寄存器阶段NACK后应立即STOP并返回错误，不能继续读出无效数据。

## 本车工程复核结果

`1-29 RDK X5 ROS正式底盘协议与ICM42670`在本轮开始前已经采用上述14字节原子读取，实际缺少的是NACK失败路径的立即退出。本轮已最小加固并通过ARMCC5全量编译，未改动目标工程的WHO_AM_I `0x47`、±2000dps/±16g、温度公式、软件I2C引脚和ROS遥测结构。

## 避坑规则

1. 先检查目标工程实际调用链和map文件，不要看到参考工程修复记录就重复重写。
2. 参考工程的器件ID、量程、寄存器值、温度公式、HAL/标准库平台和安装方向必须逐项确认，不能随突发读函数一起复制。
3. 静态检查和编译只能证明代码路径成立；实机还必须验证WHO_AM_I、静止噪声、正负旋转方向、温漂、采样频率和总线波形。
4. 若实机仍有尖峰，先保存原始14字节帧、读取错误计数和时间戳，再排查供电、上拉、线长、采样同步和传感器配置，不要先用强滤波掩盖数据损坏。
