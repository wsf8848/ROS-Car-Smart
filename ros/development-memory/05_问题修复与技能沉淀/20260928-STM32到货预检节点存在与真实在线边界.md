# STM32到货预检：设备节点存在不等于真实在线

- 日期：2026-09-28
- 状态：已闭环

## 问题一：串口节点存在容易被误判为STM32已连接

- 首版脚本只检查`/dev/ttyS5`是否为字符设备；RDK即使没有接STM32，该节点仍存在且当前用户可读写。
- 修复后报告拆分为`device_node_present`和`telemetry_validated`。只有显式`--probe-seconds`只读打开串口并收到合法73字节TELEMETRY、CRC为0、数值有限，才标记STM32链路已验证。
- 当前真实结果：`/dev/ttyS5`节点存在、115200配置未验证、没有稳定by-id别名、遥测探测尚未运行；不得写成STM32在线。

## 问题二：未加载ROS环境导致依赖误报缺失

- 直接执行`/opt/ros/humble/bin/ros2 pkg prefix`但未source setup时，Nav2、SLAM Toolbox和robot_localization被误报未安装。
- 修复为在`bash -lc`中先source`/opt/ros/humble/setup.bash`再查询。当前三项依赖均实测安装于`/opt/ros/humble`。

## 验证与产品呈现

- 预检脚本默认不打开串口、不发送任何命令；只有操作者显式指定probe秒数时才只读接收，且底盘、虚拟STM32、任务执行器或Nav2运行时拒绝探测。
- 网站新增认证保护的`/api/commissioning`和顶部“联调检查”弹窗。真实浏览器显示：协议通过、串口节点存在但未验证、STM32遥测未验证、安全空闲、ROS依赖完整、运动测试禁止。
- 当前阻塞项明确为“尚未执行STM32遥测只读探测”和“尚未完成实体底盘与安全验证”；未登录访问接口返回401。

## 可复用规则

- Linux串口节点、权限和波特率配置只能证明“具备尝试通信条件”，不能证明外设在线；必须以合法协议帧、CRC、序号、频率和内容合理性作为在线证据。
- ROS包检查必须在目标ROS环境完成，不能只因直接调用`ros2`失败就宣称依赖缺失。
- 到货检查必须分为只读预检、车轮架空运动测试和低速落地标定三阶段；默认脚本不得直接解锁运动。
