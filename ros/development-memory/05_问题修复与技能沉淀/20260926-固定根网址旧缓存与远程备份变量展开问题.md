# 2026-09-26 固定根网址旧缓存与远程备份变量展开问题

## 问题一：功能代码存在但固定网址看不到新控件

- 现象：板端新版文件包含Windows语音开关和地图/LD14切换逻辑，但用户通过固定根网址仍可能看不到按钮或按钮点不动。
- 根因：首页由`SimpleHTTPRequestHandler`默认提供，没有禁止缓存；浏览器可能复用旧`index.html`，也可能形成新HTML与旧JS/CSS混用。
- 修复：首页`/`与`/index.html`发送`no-store`、`Pragma: no-cache`和过期头；JS/CSS/SVG统一使用每次发布变化的查询版本并允许immutable缓存。
- 验证：固定根网址不带查询参数返回新版按钮；真实浏览器语音开关、LD14主视图与最小化均可操作。
- 复用规则：以后新增或修改任何前端功能都必须更新统一资源版本号，并从固定根网址做一次无查询参数验收，不能只检查板端文件。

## 问题二：PowerShell远程SSH命令提前展开Bash变量

- 现象：在PowerShell双引号SSH命令中使用远端`$b`变量，变量在本地被提前展开为空，导致`mkdir`错误指向已有正式文件路径，预发布备份没有建立。
- 影响：本次没有删除文件，正式发布成功；随后建立了发布后恢复快照。由于预发布旧版快照未生成，不能声称具备本次发布前的一键回滚副本。
- 修复与规则：涉及远端Bash变量、`$(...)`或通配符时，优先使用PowerShell单引号包住完整远端脚本，或上传独立脚本再执行；执行备份后必须`find`/校验文件数量和大小，再开始覆盖部署。
- 后续要求：发布流程固定为“建立备份 -> 列出并校验备份 -> 上传临时目录 -> 原子安装 -> 重启 -> 根网址复验”。备份失败必须停止覆盖，除非已明确记录风险并有其他恢复来源。

## 2026-09-28追加：同版本查询参数导致二次脚本修复仍被缓存

- 现象：任务状态面板新卡片已出现，但下方三行仍显示旧“当前阶段/底盘控制/地图来源”。板端`live.js`已经包含修复，真实浏览器仍执行旧初始化逻辑。
- 根因：第二次只更新`live.js`，仍沿用`?v=20260928-taskstatus1`；脚本按immutable策略缓存，刷新固定根网址只更新HTML，未强制重新取得同URL脚本。
- 修复：统一资源版本提升为`20260928-taskstatus2`，重新生成并部署`index.html`；固定根网址刷新后显示“任务状态/就绪检查/阻塞原因”。
- 回归：真实浏览器显示“安全锁定、1/6、等待实体底盘验收”；暂停/取消disabled，“打开巡逻”enabled。
- 强制规则：一次发布周期内只要JS/CSS内容再次变化，就必须再次提升资源版本；不能认为“本轮已经升过一次版本”就继续复用旧查询参数。
