# 2026-09-26 ROS2仿真与UART5虚拟联调问题闭环

## Nav2测试服务正常停止被误报failed

- 现象：`rclpy`默认信号处理先shutdown，finally再次shutdown触发`rcl_shutdown already called`；地图包装脚本收到TERM后返回143。
- 修复：测试Python节点用`SignalHandlerOptions.NO`和显式`try_shutdown`；Shell包装脚本捕获TERM、精确终止子PID并返回0。
- 回归：服务停止后为inactive、not failed，且无残留Nav2/地图/虚拟机器人进程。

## 地图服务器与导航栈的生命周期依赖

- 现象：只启动`navigation_launch.py`不会创建静态地图服务器，规划器没有地图。
- 修复：建立独立手动测试地图服务，先configure/activate地图，再启动Nav2栈；三个服务均保持disabled。
- 回归：`/map`唯一测试发布者、七个Nav2核心节点active，单点/取消/3航点/不可达目标均得到预期Action结果。

## 串口断开时systemd依赖导致驱动被一起停止

- 现象：仿真驱动服务使用`Requires=bee-virtual-stm32`，虚拟端点停止时驱动也变inactive，不能测试重连。
- 修复：改为`Wants`，让驱动在端点消失时继续运行并周期重试稳定PTY软链。
- 回归：虚拟端点停止时驱动保持active；端点恢复后重新收到`/chassis/status`。

## SIGTERM回调写串口可能阻塞退出

- 现象：驱动收到TERM后在信号回调写零帧，在端点异常时可能卡住，systemd最终SIGKILL。
- 修复：信号回调不做潜在阻塞I/O，只关闭rclpy；安全停车由STM32独立350ms合法控制帧看门狗保证。
- 回归：正常停止为inactive；暂停驱动后虚拟STM32独立置命令超时并归零。

## 可复用结论

- 仿真服务也必须验证停止路径，active测试通过不代表systemd生命周期正确。
- 串口驱动要能独立存活并重连，不应因设备端服务停止而被依赖关系级联关闭。
- 停车安全不能依赖Linux进程退出时“最后再写一帧”，实体STM32本地看门狗必须是最终保障。
- CRC错误会自然造成下一有效帧序号缺口，诊断中可同时增加CRC计数和跳号计数，这是两种不同证据而非重复错误。

## 最终复审新增回归

- 九图层发布器此前仍使用rclpy默认信号处理，在短时间重复start/stop时可能以`rcl node's context is invalid`退出。最终统一为关闭默认信号处理、SIGINT/SIGTERM显式`try_shutdown`，连续ROS话题、WebSocket和停止检查均通过。
- Humble执行器在显式context shutdown过程中偶发把内部`InvalidHandle`抛到`spin()`调用层。底盘驱动只在自身已经收到终止信号时吞掉该异常；正常运行期间的任何其他异常继续抛出，避免掩盖真实故障。
- systemd停止验收必须同时检查`is-active`和`is-failed`；仅看到进程消失或inactive不足以证明退出路径正确。
