# RDK无可靠RTC时的浏览器自动校时

- 日期：2026-09-29
- 状态：已闭环运行时方案，物理断电待验证

## 问题

- 板端虽然存在RTC设备节点，但系统和RTC均比Windows落后整整一天；仅检查`/dev/rtc0`存在会错误地把陈旧RTC当可信时间。
- 当前系统没有可用NTP服务，隔离热点环境也不能保证互联网时间源。

## 解决方案

- 管理员登录Bee网页后，使用浏览器UTC自动校时，并在页面可见期间每10分钟复核。
- 以受限root助手设置系统时钟，参数、年份范围和异常跳变都在助手内二次校验。
- 持久保存上次可信时间；启动时选择系统、RTC和可信记录中的最新合法值，RTC不可用时仍可防止时间倒退。
- NTP一旦可用则自动成为最高优先级，浏览器不会覆盖已同步NTP。

## 已验证规则

- RTC节点存在不等于断电保持可靠，必须做物理断电测试才能确认。
- 无NTP/无可靠RTC时，浏览器时间适合车载局域网内的自动运行时校准，但必须要求登录、同源、严格JSON、固定助手和审计日志。
- 可信时间文件只能防倒退，不能替代精确时间源；开机后仍需浏览器或NTP重新校准。
- 时间状态必须公开来源，不能统一显示成“RTC可信”。
- PowerShell经SSH部署复杂Bash逻辑时应上传固定脚本执行，不要继续叠加多层`$变量`和命令替换转义。
