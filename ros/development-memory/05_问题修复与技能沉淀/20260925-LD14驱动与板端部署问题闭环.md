# 2026-09-25 LD14驱动与板端部署问题闭环

## 已验证的LD14驱动问题

- 厂家ROS2驱动对LD14型号`ver=9`遗漏230400波特率分支，需明确配置230400。
- LD14串口不应开启RTS/CTS硬件流控；开启会造成实际硬件链路异常。
- 固定设备别名`/dev/LD14`时，不需要依赖libudev运行时自动枚举；板端缺少`libudev-dev`时可去除此非必要依赖。
- 原主循环无新帧时忙等，单核CPU接近100%；等待路径增加1ms sleep后约为20%。
- 接收线程和ROS发布线程共享帧数据必须加锁并以完整快照方式读取，否则可出现点数异常或全inf帧。
- 单次`ros2 topic echo --once`可能恰好取得启动/异常帧，不能代表持续链路质量；应使用直接`rclpy`连续订阅多帧，统计总点、有效点、频率、最近和最远距离。

## 已验证的部署问题

- PowerShell双引号远程命令里的Bash`$(...)`会被本地提前解释；优先传脚本文件、使用安全引用或拆成不含命令替换的小命令。
- PowerShell不能直接照搬Bash heredoc；跨平台生成脚本后应检查内容和换行。
- CRLF脚本在Linux可触发`$'\r'`或heredoc尾标记错误；发布前统计CR字节必须为0。
- `pkill -f`可能匹配远程shell自身命令行；应先精确核对PID/comm，再对具体PID发送信号。
- ROS2 `setup.bash`可能读取尚未定义变量；不要在source之前启用Bash `set -u`。已验证顺序为`set -eo pipefail`、source ROS、再`set -u`。
- 高频失败后即使代码已修复，systemd仍可能因`start-limit-hit`拒绝启动；先核对新文件已生效，再`systemctl reset-failed`并启动。

## 当前验证边界

- 上述结论已在RDK X5 Ubuntu 22.04 / ROS2 Humble / LD14 CP2102真实硬件上验证。
- 只证明LD14 `/scan`与Bee只读网页网关阶段；不代表STM32、里程计、IMU、SLAM、Nav2或车辆运动已完成。
