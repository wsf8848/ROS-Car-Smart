# 检查点即时回写与 Skill 沉淀规范

## 1. 每轮启动强制步骤

1. 完整读取 `README_总索引.md`。
2. 读取最新进行中任务和当前项目基线。
3. 读取本轮相关的方案、协议、接线、标定和问题记录。
4. 检查目标工程现状、版本和既有改动。
5. 在 `00_当前开发任务` 新建本轮文件，并在总索引登记“进行中”。
6. 先回写“基线审计”检查点，再修改代码或配置。

## 2. 检查点定义

以下任一项完成即构成检查点，必须立即回写：

- 需求或协议获得确认；
- 完成一个模块的代码修改；
- 编译、单测、静态检查通过或失败；
- 固件烧录完成；
- 串口/CAN/ROS 话题首次打通；
- 一个硬件或传感器完成校准；
- 一个故障找到证据根因；
- 修复完成并通过回归；
- 完成一次整车动作、SLAM、导航或巡逻验收；
- 改变版本、交付产物或下一步入口。

## 3. 每个检查点必须记录

- 时间；
- 目标；
- 实际改动；
- 涉及文件和接口；
- 执行命令或操作；
- 原始证据或证据路径；
- 失败尝试；
- 证据支持的根因；
- 最终解决方法；
- 验证结果；
- 未验证边界；
- 下一步；
- 状态：进行中、完成、失败待处理、阻塞。

没有失败尝试时明确写“无”，不得为了格式编造失败。

## 4. 分层验证规则

```text
代码检查 -> 编译 -> 固件/软件启动 -> 接口收发 -> 单模块硬件
-> 多传感器融合 -> 车轮架空动作 -> 低速落地 -> SLAM
-> 定点导航 -> 巡逻与异常恢复 -> 交付
```

任何低层通过都不能替代更高层验证。报告必须明确目前停在哪一层。

## 5. 问题闭环与 Skill 沉淀

真实问题按以下顺序记录：

1. 现象和触发条件；
2. 失败尝试及证据；
3. 根因；
4. 修复；
5. 分层回归结果；
6. 适用条件和不适用边界。

可复用结论另写入 `05_问题修复与技能沉淀`，并同步更新项目专用 Skill。仅把经过验证、会改变后续决策的经验写入 Skill；猜测和一次性日志留在任务记忆中。

修改 Skill 后必须运行：

```powershell
$env:PYTHONUTF8='1'
python C:\Users\Bee\.codex\skills\.system\skill-creator\scripts\quick_validate.py C:\Users\Bee\.codex\skills\rdk-x5-autonomous-car
```

校验通过后，才能把 Skill 检查点标记为完成。

## 6. 安全与版本规则

- 烧录和电机动作前确认目标板、供电、下载器、车轮架空和急停手段。
- 不使用未经确认的轮径、轮距、编码器计数和极性。
- 不把敏感凭据写入记忆、源码、日志或 Skill。
- 验证不过不得声明功能完成，不得发布版本。
- 删除旧产物、覆盖固件、初始化 Git 或推送远端必须处于用户授权范围内。

## 7. 每轮结束条件

- 最新任务文件已记录最后一个检查点；
- 总索引状态与任务状态一致；
- 当前基线反映真实已验证边界；
- 新问题已写入问题目录；
- 可复用且已验证的经验已更新 Skill 并校验；
- 下一轮入口明确到具体文件、硬件、命令或待确认事项。
