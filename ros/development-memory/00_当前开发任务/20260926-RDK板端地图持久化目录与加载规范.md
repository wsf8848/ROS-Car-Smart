# RDK板端地图持久化目录与加载规范

## 需求

用户确认：以后新建的地图必须保存到地瓜派板端的专用文件夹，需要时直接加载，不保存为浏览器本地临时数据。

## CP0 现状审计（2026-09-26）

- Bee网关已使用环境变量 `BEE_MAPS_ROOT`，systemd当前配置为 `/opt/bee-ros-web-console/data/maps`。
- 网关 `MapManager` 启动时创建该目录；保存调用 `nav2_map_server map_saver_cli`，生成同名 `.yaml + .pgm`。
- `/api/maps` 只列出该目录下完整地图；`/api/maps/action` 只接受 `save/load/unload`，加载只接受目录名形式的地图 ID，拒绝任意路径。
- 板端现场已确认该目录存在且当前有三组成对的 YAML/PGM 文件；服务环境变量指向该目录。

## CP1 规范固化（2026-09-26）

- 新增工程说明 `Bee ROS Web Console/deploy/MAP_STORAGE.md`，固定地图目录、文件配对、保存/加载约束和备份规则。
- 更新工程 README，明确地图只保存在 RDK X5 板端，不写入浏览器或Windows电脑。
- 现有测试地图不能直接视为真实建图；真实车辆必须在STM32、编码器、IMU、TF和SLAM完成后再保存正式地图。

## 使用流程

1. 网页开始实验/真实建图。
2. 停止建图并检查绿色可通行区、红色障碍区、深灰未知区和地图原点。
3. 点击“保存当前地图”，网关在板端地图库生成新地图 ID。
4. 需要使用时在地图管理中点击“加载”，确认 `/map` 发布和定位成功。
5. 再启动定点导航或巡逻；地图未加载、定位丢失或地图文件不完整时保持任务拒绝。

## 验证证据

- 板端目录：`/opt/bee-ros-web-console/data/maps`，目录权限和文件均由网关运行用户管理。
- systemd：`BEE_MAPS_ROOT=/opt/bee-ros-web-console/data/maps`。
- 已有网页地图管理入口：保存、刷新、加载、卸载。
- 本轮未启动真实SLAM或覆盖现有地图；雷达当前断开，真实建图/重启加载/实车导航仍待硬件恢复后验证。
