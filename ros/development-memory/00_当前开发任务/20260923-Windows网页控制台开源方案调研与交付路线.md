# 2026-09-23 Windows网页控制台开源方案调研与交付路线

## 一、用户目标

- RDK X5建立Wi-Fi热点；
- Windows笔记本连接热点后打开固定网址即可使用；
- 网页下发人工控制、建图、定位、导航、取消、路径规划和巡逻指令；
- 实时显示地图、车辆位置、雷达、路径、运动状态、电池、控制源和任务结果；
- 优先完成电脑网页端并作为客户交付主入口；
- 最后将同一能力集成到掌机，保留原蓝牙和MQTT控制。

## 二、GitHub调研结论（2026-09-23）

### 1. Vizanti ROS2：最匹配的现成原型

- GitHub：https://github.com/MoffKalast/vizanti/tree/ros2
- 许可证：BSD-3-Clause。
- 状态：未归档；ROS2分支最近提交时间为2026-08-23；仓库约270 stars、65 forks。
- 官方说明支持ROS2 Humble/Ubuntu 22.04、Jazzy/24.04，并设计为部署在机器人本机、无互联网热点环境使用。
- 默认网页：`http://<host_ip>:5000`；默认rosbridge端口5001。
- 功能定位：类似移动友好的二维RViz，支持可视化、目标点、航点、任务命令、自定义按钮和参数。
- 结论：非常适合RDK X5上的第一版验证，不必从零搭建地图和目标点交互。
- 限制：通用工具界面和通用ROS桥不等于客户产品；权限、品牌、工作流、安全限制和交付运维仍需自行完成。

### 2. rosbridge_suite + roslibjs：自研控制台的成熟底座

- rosbridge：https://github.com/RobotWebTools/rosbridge_suite
- roslibjs：https://github.com/RobotWebTools/roslibjs
- rosbridge状态：未归档，ROS2主分支，Humble有正式版本；约1246 stars、595 forks，BSD-3-Clause。
- roslibjs状态：未归档，2026-09仍有提交；约828 stars、417 forks；当前包声明BSD-2-Clause。
- 能力：浏览器通过WebSocket订阅/发布Topic、调用Service，并访问ROS图信息。
- 结论：适合自有前端快速接入ROS，但客户版不应把“可访问全部ROS”的通用桥直接暴露给浏览器。

### 3. RWS：Vizanti推荐的高性能ROS2桥候选

- GitHub：https://github.com/v-kiniv/rws
- 状态：未归档，Apache-2.0；约27 stars、15 forks。
- Vizanti说明其C++后端相对Python rosbridge可显著降低开销；具体收益需在RDK X5实测，不能直接当作本车结论。
- 结论：可作为Vizanti性能优化候选，不作为客户控制API的安全边界。

### 4. ROSboard：适合轻量监控，不足以单独完成导航控制台

- GitHub：https://github.com/dheera/rosboard
- 状态：未归档，2026-08仍有提交；约1160 stars、212 forks，BSD-3-Clause。
- 优点：ROS1/ROS2兼容、移动端友好、轻量、打开 `http://机器人IP:8888` 即可显示Topic。
- 不足：核心定位是Topic可视化，不是完整Nav2地图选点、Action管理和巡逻工作流。
- 结论：可借鉴状态卡片与诊断显示，不选作主控制台。

### 5. Foxglove：适合研发诊断，不作为客户主控台

- ROS2方向：https://github.com/foxglove/foxglove-sdk
- 优点：高性能遥测、3D/时序分析和研发调试能力强。
- 不足：面向通用调试与数据分析，不是本车定制的操作流程；客户交付、离线自托管和品牌化需要额外评估。
- 结论：保留为工程师诊断工具，不作为客户的固定网址主界面。

### 6. Webviz：不建议新项目采用

- GitHub：https://github.com/cruise-automation/webviz
- 仓库虽未标记归档，但代码最近推送停留在2022-12，README也建议关注Foxglove。
- 结论：不作为本项目新开发主线。

## 三、最终选型

采用“两步走”：

1. **快速验证原型**：在RDK X5部署Vizanti ROS2，尽快验证Windows通过热点访问、地图/雷达/位姿显示、地图选点、路径和航点任务。
2. **客户正式交付**：开发自有 `Bee ROS Web Console`，复用成熟ROS桥接思想和前端组件，但通过自有受控网关暴露有限业务API，不直接给浏览器ROS超级权限。

不直接将Vizanti换皮后当最终交付，也不从零重复发明ROS网页通信。

## 四、正式交付架构

```text
Windows浏览器 / 掌机WebView
        │ 连接RDK热点
        │ http://固定IP/（建议最终固定为80端口）
        ▼
Nginx：离线前端资源、反向代理、访问限制
        ├── 静态响应式Web/PWA
        └── /api + /ws
                 ▼
        bee_web_gateway（受控ROS网关）
        ├── 认证、角色、心跳、限速、审计
        ├── 状态与地图WebSocket
        ├── NavigateToPose/FollowWaypoints Action客户端
        ├── 建图、保存、定位、取消和代价地图服务
        └── 网页人工速度 -> ROS内部速度仲裁
                 ▼
        ROS2/Nav2/SLAM/bee_base_driver
                 ▼ UART5
        STM32控制源仲裁、安全保护、四轮PID
```

## 五、网页功能范围

### 第一版MVP

- RDK/STM32/雷达/IMU在线状态；
- 当前控制源、速度、电池和故障；
- 地图、车辆位姿、雷达点和路径；
- 网页方向/摇杆人工控制，必须有按住才运动、松开归零和通信超时；
- ROS模式进入/退出、停止和急停；
- 初始位姿和地图点击目标点；
- 导航进度、成功/失败原因和取消。

### 完整交付版

- 建图启动/停止/保存/地图选择；
- 全局路径、局部路径、代价地图和障碍显示；
- 航点添加、排序、删除、保存和循环巡逻；
- 暂停、恢复、跳过、失败重试、低电量策略；
- 操作员/管理员/只读角色；
- 登录失败限制、审计日志、诊断导出；
- 开机自启、服务健康、配置备份和恢复；
- 全资源本地化，热点断网时页面不依赖CDN。

## 六、热点和固定网址方向

- RDK作为AP，使用固定网段和固定网关IP；建议值可为 `192.168.50.1`，最终须先检查与现有网络冲突再定稿。
- 客户主入口优先使用固定IP根网址，例如 `http://192.168.50.1/`，避免要求客户记端口。
- 可同时提供 `http://bee-car.local/` 作为友好名称，但不能只依赖Windows的mDNS解析。
- 热点使用WPA2/WPA3；即使是离线局域网，网页仍需登录与控制权限。
- 不对热点开放通用rosbridge/RWS端口；原型验证端口仅在开发模式开放。

## 七、数据和控制链路

- 地图：`nav_msgs/OccupancyGrid`变化时更新底图，浏览器分层绘制。
- 实时叠加：车辆位姿、LaserScan、全局路径、局部路径、目标点、航点和障碍物通过WebSocket节流推送。
- 导航：网页目标 -> 网关校验 -> `NavigateToPose` Action -> Nav2。
- 巡逻：网页航点列表 -> 网关校验 -> `FollowWaypoints`或任务节点。
- 人工ROS遥控：网页心跳/摇杆 -> RDK内部ROS速度仲裁 -> `/cmd_vel` -> `bee_base_driver` -> STM32。
- 人工抢占：蓝牙/MQTT优先级仍高于ROS；STM32负责最终控制源仲裁和安全停车。

## 八、调整后的实施顺序

1. 阶段0至阶段3仍不变：旧功能基线、正式协议、STM32增量、RDK底盘驱动。
2. 板对板通信稳定后立即部署Vizanti原型并打通Windows热点访问。
3. 同时建立自有响应式前端、受控网关、Nginx和systemd骨架。
4. 每完成雷达、里程计、SLAM、AMCL、Nav2和巡逻中的一层，就立即把该层接入网页并用网页验收。
5. Windows控制台通过完整客户验收后，再将同一页面以PWA或Android WebView方式集成到掌机。
6. 掌机原蓝牙和MQTT页面、协议与人工接管能力保持不变。

## 十、Bee ROS Web Console 最终UI范围冻结

- 用户决定：以 Vizanti ROS2 作为验证参考，最终实现自有 `Bee ROS Web Console`。
- UI开发顺序：先完成最终整体UI和响应式布局，再按页面契约逐步接入ROS数据与控制功能；UI信息架构不得因后续接口实现而反复推翻。
- 桌面首屏必须包含：
  - 顶部连接与安全栏：车辆名称、RDK/STM32/LD14/IMU在线状态、Wi-Fi信号、当前控制源、ROS模式、急停入口；
  - 左侧地图主视图：地图、车辆位姿、雷达点云、全局路径、局部路径、目标点、航点、障碍/代价区域和比例尺；
  - 地图工具：设置初始位姿、发送目标、清除目标、添加/编辑/排序航点、保存航点任务；
  - 右侧任务控制：自主导航、导航避障、路径规划、定点/多航点巡逻四项核心能力，任务状态、进度、取消、暂停、恢复、重试和失败原因；
  - 底部遥测区：线速度、角速度、四轮速度、电池、定位质量、雷达频率、控制延迟和最近故障；
  - 始终可见的人工接管与急停区域：网页人工遥控按住才运动、松开归零，蓝牙/MQTT人工接管状态明确显示。
- 视觉方向：深色工业控制台、低饱和蓝灰底、青绿色作为运行/导航主色、橙色作为警告、红色仅用于急停和危险；地图区域最大化，卡片少而信息密度高，禁止营销式大卡片和装饰性渐变。
- 响应式要求：Windows笔记本为主；平板/掌机窄屏时地图优先，右侧任务栏折叠到底部抽屉，急停和控制源状态保持固定可见。
- 交互状态必须覆盖：连接中、在线、断开、ROS未启动、地图未加载、定位丢失、导航执行、导航暂停、任务失败、急停触发和人工接管。
- 本轮UI只做设计和可视化，不宣称已接入ROS、Nav2或实车；功能接入从地图/状态只读显示开始，再接入目标点、取消、巡逻和人工控制。
