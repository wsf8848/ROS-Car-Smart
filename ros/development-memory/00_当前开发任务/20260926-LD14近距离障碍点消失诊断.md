# 2026-09-26 LD14近距离障碍点消失诊断

## 目标与现象

- 用户实测：手向LD14靠近时，按常理应看到回波点向雷达中心移动，但实际靠近到一定距离后整片点消失。
- 本轮需要区分：LD14物理近距盲区、ROS驱动`range_min`无效值处理、Bee网关过滤和网页二次过滤，不能把“实时点消失”误解释成已经建图的固定障碍变化。
- 当前硬件仍为RDK X5 + LD14，无STM32和整车；不改动运动、导航和急停安全禁用状态。

## 检查点1：代码过滤链审计

- 时间：2026-09-26（Asia/Shanghai）。
- Bee网关仅保留`math.isfinite(distance)`且位于ROS消息`range_min~range_max`内的回波。
- 网页又明确过滤`range < 0.3m`的点，因此任何小于30cm的近距离读数不会绘制；遥测文字也标注“LD14量程下限0.3m”。
- 前端每收到一帧会清空上一帧点云再绘制当前帧，因此被判无效的近距离方向不会保留旧点；这与SLAM占据栅格中的固定障碍不是同一种显示。
- 初步判断：用户将手靠近到约30cm以内时，点消失符合当前量程/过滤逻辑；仍需读取板端真实`/scan.range_min`和近距数据验证，不能只凭代码下结论。
- 状态：进行中。

## 检查点2：原始ROS数据和厂家源码证据

- 时间：2026-09-26（Asia/Shanghai）。
- 板端`/scan`实测：`range_min=0.3000000119m`；约`0.302~0.308m`仍有有效点，更近方向变成`.inf`。
- 厂家ROS2驱动`main.cpp`把`scan.range_min=0.3`写死，并将`<=range_min`的数据强制转换为无穷大；网页随后又过滤`<0.3m`，所以15~30cm近距回波在驱动和网页两层被丢弃。
- 本地随雷达提供的《LD14激光雷达数据手册》标称测距范围为`0.15~8m`（80%目标反射率条件）。因此当前30cm下限不是本项目硬件标称极限，而是厂家ROS示例采用的保守阈值。
- 修复决定：驱动消息和网页绘制统一改为0.15m；15cm以内继续视为无效盲区。近距离低反射、斜面、手掌姿态或强光仍可能造成丢点，不能把15cm写成所有材质必然可靠。
- 状态：根因确认，开始修改和板端验证。
