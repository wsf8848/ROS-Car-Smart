# RDK板端网站与环境灾备备份

## 需求

用户要求把本次网站、板端环境配置和重要资源备份到电脑对应工程目录，以便RDK板或存储卡损坏后快速恢复；以后用户说“备份”时沿用当前流程。

## CP0 备份范围审计（2026-09-26）

- 原有板端脚本仅备份网站前端、网关、配置、部署、工具、地图、LD14质量资料和systemd单元。
- 缺少ROS工作空间、环境文件脱敏副本、热点配置脱敏副本、systemd运行清单和网络状态清单。

## CP1 备份脚本增强（2026-09-26）

- 更新 `Bee ROS Web Console/tools/backup_bee_console.sh`：新增 `/opt/bee_ros_ws`、脱敏 `/etc/bee-ros-web-console.env`、脱敏热点连接、systemd清单、NetworkManager连接清单和IP地址清单。
- 真实密码、PBKDF2哈希、会话签名密钥、热点PSK、SSH私钥和Cookie不进入电脑备份。
- 归档内增加 `host-config/README.md`，写明恢复顺序和凭据重新注入要求。

## CP3 校验结果（2026-09-26）

- 本地归档哈希与板端`.sha256`一致。
- 归档可正常解压；敏感值扫描未发现真实管理员密码或热点密码，环境和热点文件为`REDACTED`脱敏版本。
- 当前备份是“可恢复工程与配置基线”，不是可直接无条件启动的整板镜像；新板仍需安装匹配OS/ROS依赖并重新注入凭据。

## 后续“备份”固定流程

1. 先读取本文件和总索引，确认目标板IP、SSH密钥和当前服务范围。
2. 在板端执行增强版 `backup_bee_console.sh`。
3. 拉回 `.tar.gz` 与 `.sha256` 到本目录下按时间保存。
4. 校验归档SHA-256、解压完整性、包内文件清单和敏感信息脱敏结果。
5. 更新本文件、总索引、交付README和项目Skill；不得覆盖历史备份。

## 当前边界

- 本轮未备份SSH私钥、真实密码、会话密钥和热点PSK，这是有意的安全策略。
- STM32固件工程不在本次RDK板端备份归档内；如需整车灾备，应另行备份STM32独立工程和编译产物。
