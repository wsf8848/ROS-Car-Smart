# 2026-09-25 Bee网页真实 `/map` 栅格渲染与坐标验证

## 目标

- 在现有Bee只读网关中订阅标准`nav_msgs/msg/OccupancyGrid` `/map`。
- 网页根据消息中的`width`、`height`、`resolution`、`origin`和栅格数据逐格渲染。
- 颜色保持用户确认语义：可通行绿色、障碍红色、未知深灰。
- 使用明确标记的测试地图验证ROS行列方向、Y轴翻转和地图坐标换算，不把测试地图冒充SLAM实图。
- 保持真实LD14 `/scan`链路和无STM32时的控制禁用边界。

## 检查点1：基线审计

- 时间：2026-09-25（Asia/Shanghai）。
- 当前板端`bee-ld14.service`与`bee-web-console.service`已运行，网页只读接入真实`/scan`。
- 当前网关没有`/map`订阅；前端仅生成42×23全未知占位格，未使用真实OccupancyGrid元数据。
- 当前没有STM32、编码器、IMU和动态TF；本轮只验证地图消息的数据契约、渲染和坐标换算，不启动或宣称SLAM/Nav2已完成。
- 实施方案：网关采用Transient Local可靠QoS订阅`/map`；地图仅在新版本到达时通过WebSocket发送；前端按ROS底行到SVG顶行进行Y轴翻转，并用分辨率、原点和原点偏航计算地图坐标。
- 测试地图使用专用frame标识`bee_test_map`并在网页醒目标注；测试发布器不设为开机自启，正式SLAM接入前必须停止。
- 状态：进行中，下一步实现网关、前端和测试地图发布器。

## 检查点2：`/map`数据契约与前端实现

- 时间：2026-09-25（Asia/Shanghai）。
- 网关新增标准`nav_msgs/msg/OccupancyGrid` `/map`订阅，QoS为Reliable、Transient Local、Keep Last 1，与SLAM/静态地图发布语义匹配。
- WebSocket地图负载包含：版本、frame、测试标志、宽高、分辨率、原点x/y/yaw、绿/红/灰计数和原始栅格数组；相同地图用元数据＋CRC32摘要抑制重复发送，不长期保存第二份完整元组。
- 前端按ROS数组`index = row * width + column`读取，SVG显示时执行`svgRow = height - 1 - rosRow`，解决ROS地图Y轴向上而屏幕Y轴向下的方向差异。
- 点击坐标换算包含：SVG `preserveAspectRatio=xMidYMid meet`产生的留白、画布缩放、格子行列、分辨率、地图原点和平面原点偏航；不再把浏览器像素百分比直接当map坐标。
- 栅格颜色：`value < 0`深灰unknown，`0~49`绿色free，`>=50`红色occupied；点击只产生蓝色选择标记和坐标读数，不开放导航或标定下发。
- LD14继续显示为真实独立扫描层，但页面明确标记“暂无map→laser TF配准”，避免误解为点云已叠加到地图坐标系。
- 新增`tools/test_map_publisher.py`：48×30、0.20m/格、原点(-4.0,-2.5)、原点偏航10°、frame=`bee_test_map`，同时包含绿色、红色和深灰格子。
- 新增`bee-test-map.service`，不带`[Install]`且不enable，只允许当前测试阶段手动启动；真实SLAM开始前必须停止。
- 验证：Python网关/测试发布器`py_compile`通过，`node --check frontend/live.js`通过，正式`index.html`重建成功；待部署文件CR字节均为0。
- 状态：代码完成，下一步板端备份、部署并实测ROS话题、WebSocket和浏览器坐标。
