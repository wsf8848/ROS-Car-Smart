# Bee 网页板卡健康实时遥测

- 日期：2026-09-28
- 状态：已完成
- 目标：在不启用任何运动服务的前提下，为 Bee ROS Web Console 增加 RDK X5 的 CPU 温度、CPU 使用率、内存、磁盘、运行时长和更新时间实时显示。

## 检查点1：基线审计（已完成）

- 当前正式前端版本基线为 `20260928-patrol9`；网站固定入口为 `http://192.168.127.10:8080/`，网关代码为 `gateway/bee_gateway.py`，前端主要逻辑为 `frontend/live.js` 与 `frontend/live.css`。
- 现有网关已有认证保护、`/api/diagnostics`、`/api/health`、地图/巡逻/相机和受控电源接口，但没有板卡 CPU 温度、CPU/内存/磁盘占用的专用只读接口。
- 现有顶部工具区已经动态加入“雷达诊断”和“地图管理”；为避免继续挤占六项车辆实时状态，本轮新增独立“板卡健康”按钮与紧凑弹窗。
- 数据策略：CPU 从 `/proc/stat` 连续采样差值计算；内存从 `/proc/meminfo` 计算；根分区使用 `os.statvfs('/')`；温度枚举 `/sys/class/thermal/thermal_zone*/temp`，不得假定固定温区编号。接口异常必须返回不可用状态，不能伪造为 0。
- 前端仅在健康窗口打开且页面可见时约每 2 秒刷新；关闭窗口或切到后台时停止高频请求。阈值只作为“网页预警”，不冒充芯片官方降频阈值。
- 安全保护边界：不得启动 `bee-base-driver`、实验 SLAM、Nav2 仿真或虚拟 STM32；导航、巡逻、人工接管和急停仍保持实体底盘未验收阶段的 fail-closed 状态。
- 下一步：实现认证只读 API、健康弹窗和状态颜色，完成本地语法/构建检查后部署到板端并实测。

## 检查点2：板端只读数据源确认（已完成）

- 板端可访问；实测温区为 `thermal-ddr` 与 `thermal-cpu`，本轮必须优先选择 `thermal-cpu`，不能写死 `thermal_zone0`。
- 只读采样时 CPU 温度约 44.1°C；内存总量约 3.0GiB、可用约 2.34GiB；根分区约 61.2GB、`df`显示使用18%；`/proc/stat`、`/proc/meminfo`、`/proc/uptime`和`statvfs('/')`均可用。
- 安全服务状态：`bee-web-console=active`、`bee-ld14=active`；`bee-base-driver`、`bee-test-map`、`bee-nav2-map`和`bee-experimental-slam`均为 `inactive`。
- 板端当前前端资源版本为 `20260928-patrol9`；本地源文件哈希与板端网关、JS、CSS一致，确认从当前正式基线增量修改。

## 检查点3：本地实现与静态验证（已完成）

- 后端新增低开销 `SystemHealthMonitor`：后台约1秒采样并缓存，不为每个HTTP请求启动 `top/df` 等外部进程；CPU按 `/proc/stat`两次采样差值计算，温区自动优先CPU/SoC，内存、根分区和运行时长均由内核接口读取。
- 新增经现有登录认证保护的 `GET /api/system/health`。返回UTC采样时间、CPU使用率/温度/温区、内存、根分区、运行时长及错误列表；缺失数据返回 `null` 和明确错误，不伪造在线或0值。
- 前端新增顶部“板卡健康”按钮和独立紧凑弹窗，显示CPU温度、CPU、内存、磁盘、运行时长和数据状态；正常/网页预警/危险/不可用分别使用绿色/黄色/红色/灰色。
- 弹窗打开且页面可见时每2秒请求，关闭弹窗或页面切后台时停止轮询；没有对每帧状态进行语音播报。
- 本地验证：`python -m py_compile gateway/bee_gateway.py`退出0；`node --check frontend/live.js`退出0；`tools/build-frontend.ps1`成功生成正式HTML。发布版本调整为 `20260928-health1`。
