# 地图目标点放大与长按定向

- 日期：2026-09-29
- 状态：已完成（网站交互与浏览器验证；实车Nav2仍待底盘到货）
- 目标：放大地图目标点、方向箭头端点和巡逻航点的屏幕可见尺寸，并把方向调整改为“左键长按后拖动，松开固定”，提升大地图和浏览器缩放场景下的操作命中率。

## 检查点 1：基线审计（已完成）

- 当前真实地图坐标仍由 OccupancyGrid 的 resolution、origin、地图尺寸和 SVG 视口换算，目标点视觉放大不得改变 map 坐标或 Nav2 yaw。
- 现有版本已经支持拖动箭头端点，但目标圆点半径固定为地图格单位；地图范围增大时屏幕视觉尺寸会明显变小，而且只有端点可以开始拖动。
- 本轮只修改前端目标/航点视觉尺寸、指针命中范围、长按状态机、自动化测试和资源版本；不修改后端任务接口，不解除 motion safety gate，不把浏览器测试写成实车导航通过。
- 保护边界：原蓝牙、MQTT、STM32固件、地图原始数据、巡逻持久化格式和Nav2任务协议均不改动。

## 检查点 2：实现（进行中）

- 目标设计：目标点保持约20px直径的可视尺寸，方向箭头保持约45px长度；地图越大时自动提高SVG局部缩放，不依赖固定格子尺寸。
- 左键短点目标点不改变yaw；按住180ms后进入方向拖动，松开时最后一次更新并固定yaw；pointer cancel/lost capture会安全退出。
- 目标中心、箭杆和端点都可触发长按，增加透明命中区；巡逻航点同步放大，现有绿色可通行格校验和安全锁保持不变。

## 检查点 3：首次板端浏览器验证与问题闭环（进行中）

- 本地 JavaScript 语法检查通过，前端首次以版本 `20260929-goalhold1` 部署；本地与板端 `live.js/live.css/index.html` SHA-256逐文件一致。
- 首次远程备份命令因 Windows PowerShell 展开远程 Bash `$stamp` 失败，错误发生在复制和覆盖正式文件之前；立即复核板端三文件仍为旧哈希、`/tmp/live.js`不存在，再改为单引号远程命令完成备份和部署。该现象符合既有“PowerShell不得展开远程变量”的问题规则。
- 1280×720真实Windows浏览器已确认加载新资源，目标中心点约 `23.17×23.17px`，新操作提示可见，页面无横向溢出，导航和巡逻运动按钮继续禁用。
- 首次真实拖动发现：pointerup后浏览器可能补发普通click，导致地图目标被重新选择到松手位置。根因是拖动状态在click到达前已复位；修复为目标点pointerdown及pointerup后设置450ms地图click抑制窗口，保证短点不改yaw、拖动松手只固定方向且不移动目标坐标。
