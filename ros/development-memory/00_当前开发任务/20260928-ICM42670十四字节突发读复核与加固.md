## 检查点1：基线审计（已完成）

### FY101S已验证问题与修复依据

- 旧方式把温度、加速度和陀螺仪数据拆成多次独立寄存器读取；传感器高ODR刷新时，高低字节可能跨越两个采样周期。
- 在零点符号翻转附近，高字节和低字节错配可拼出约`±256`计数的假尖峰。
- FY101S最终修订版改为从`TEMP_DATA1 (0x09)`开始，在同一次I2C事务中连续读取14字节：温度2字节、加速度XYZ 6字节、陀螺XYZ 6字节；前13字节回ACK，最后1字节回NACK后STOP。

### 目标工程实际状态

- `Hardware/ICM42670.c`已经定义`ICM42670_SAMPLE_BYTE_COUNT = 14U`。
- `ICM42670_ReadSample()`已经通过一次`ICM42670_ReadRegisters(0x09, Raw, 14)`取得整帧，再从`Raw[0]..Raw[13]`拼接7个有符号16位字段。
- `ICM42670_ReadRegisters()`当前为一次START写寄存器地址、重复START切读、连续读取全部字节；`ICM42670_SendAck(Index + 1 == Length)`的语义为非末字节发送`0`（ACK）、末字节发送`1`（NACK），时序正确。
- `Project.uvprojx`实际引用`.\Hardware\ICM42670.c`，现有map文件也证明`RosProtocol_UpdateImu -> ICM42670_ReadSample -> ICM42670_ReadRegisters`已经链接到固件。
- 全工程搜索未发现另一条把六轴数据拆成逐寄存器读取的有效调用路径。

### 审计结论

目标工程在本轮开始前已经具备FY101S同类的14字节原子突发读，不能盲目复制STM32G0版本，也不能覆盖目标工程的WHO_AM_I `0x47`、±2000dps/±16g配置、温度公式和板级引脚。当前真实薄弱点是：地址阶段发生NACK时，通用连续读取函数仍会继续时钟出数据；虽然调用者最终会丢弃本帧，但应立即STOP退出，避免异常总线上的无效读取。
