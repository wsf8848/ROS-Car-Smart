# Bee网页目标朝向与巡逻航点编辑

- 日期：2026-09-28（Asia/Shanghai）
- 状态：网页交互、板端草稿持久化和安全锁验收完成；实车任务执行待STM32/定位/Nav2到位
- 目标：完善目标方向箭头交互、巡逻航点编辑和有限巡逻次数设置，为三阶段交付的第二、第三阶段提供可操作网页入口。

## 检查点1：基线审计（已完成）

- 当前真实`/map`已经使用OccupancyGrid的分辨率、原点和origin yaw完成浏览器坐标与map坐标换算。
- 当前蓝色选点仅为圆点；“导航到此点”仍由旧静态脚本给出演示反馈，没有可编辑yaw。
- 当前巡逻区的4个航点、任务名称和循环模式是静态样稿；没有增删、排序、逐点朝向或次数输入。
- 网关`/api/tasks/action`保持fail-closed，实体STM32、里程计、IMU、TF和Nav2未验收前所有运动任务均拒绝，`motion_enabled=false`。
- 本轮保护边界：不修改STM32、蓝牙或MQTT；允许在真实地图坐标中编辑和持久保存任务草稿，但不能绕过安全门启动车辆。
- 计划验证：朝向拖拽与数值输入、航点新增/选择/删除/上下移动、地图隔离、1~99次设置、刷新恢复、请求结构校验、导航/巡逻拒绝安全门、1440×1000/1024×900/1536×768布局与控制台错误。

## 检查点3：地图可操作编辑模式与数据安全加固（已完成）

- 发现第一版巡逻编辑器使用全屏模态遮罩，虽然按钮显示“地图点击添加：开启”，但遮罩会截获鼠标，导致地图无法实际添加航点。
- 修复为双形态编辑器：普通状态保持居中完整编辑；开启地图添加后切换为右侧不遮断页面的浮动面板，遮罩层不接收鼠标，地图继续可点，面板自身仍可编辑、排序和保存；按钮明确显示“结束地图添加”。
- 地图加载/卸载动作后自动刷新任务上下文；检测地图切换时清空不属于当前地图的本地编辑状态，避免航点误绑定。
- 后端保存草稿前确认对应`.yaml + .pgm`地图真实存在；更新已有草稿时禁止改变`map_id`，杜绝跨地图覆盖。
- 坐标与yaw校验显式拒绝Python布尔值、非有限值、超大坐标和超出`[-π, π]`的朝向；任务执行请求同步使用相同边界。
- 发布资源版本更新为`20260928-patrol2`；`node --check`、`python -m py_compile`、前端构建全部通过，生成页中`live.js/live.css`均只有一份且版本一致。
