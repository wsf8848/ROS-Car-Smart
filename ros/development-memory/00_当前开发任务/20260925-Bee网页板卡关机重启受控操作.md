# 2026-09-25 Bee网页板卡关机/重启受控操作

## 目标与边界

- 在Bee ROS Web Console右上角新增“重启板卡”和“关闭板卡”两个按钮。
- 点击必须经过二次确认，确认后调用同源受控API；后端只允许固定`reboot`和`poweroff`动作，不开放任意shell命令。
- 操作响应先返回浏览器，再延迟约2秒执行，页面显示板卡即将离线。
- 自动验收只使用干运行模式，不在测试期间真正重启或关闭板卡；真实模式部署完成后由用户主动点击触发。
- 当前车载局域网开发阶段尚无登录认证；接口至少执行同源检查、JSON白名单、请求大小限制、重复请求限流和journal审计。正式客户交付前必须把系统电源操作纳入登录/管理员权限。

## 检查点1：基线审计

- 时间：2026-09-25（Asia/Shanghai）。
- 当前网页右上角已有4个状态、模式和急停按钮；适合在急停之前加入两项板卡系统操作，不改变地图和任务布局。

## 检查点2：受控API与右上角UI实现

- 时间：2026-09-25（Asia/Shanghai）。
- 右上角在模式与急停之间新增`重启板卡`、`关闭板卡`按钮；保留原状态栏、地图、任务和急停布局。
- 两个按钮均弹出自定义二次确认框，明确提示网页/ROS2/雷达将离线，关机后需重新上电；支持取消、遮罩关闭和Esc取消。
- 新增同源`POST /api/system/power`，请求体必须严格等于`{"action":"reboot"}`或`{"action":"poweroff"}`；额外字段、其他动作、非JSON、缺失/异源Origin和超大请求均拒绝。
- 后端只通过固定字典映射到参数数组：`sudo -n systemctl reboot`或`sudo -n systemctl poweroff`，不使用shell字符串、不接受命令、参数或路径输入。
- 接口使用全局pending锁拒绝重复电源操作，先返回HTTP 202，再延迟2秒执行；journal输出`BEE_POWER_AUDIT`接受/执行/失败记录。
- 增加`BEE_POWER_DRY_RUN`：自动测试阶段只记录动作、不重启/关机；正式服务配置为`0`。
- 前端提交期间禁用两个按钮，显示成功/失败toast；真实模式接受后把RDK状态改为“即将重启/关机”。
- 当前安全边界：隔离车载局域网开发阶段使用同源检查；正式客户交付前必须加入登录和管理员权限，不能长期把系统电源操作开放给同网段任意浏览器。
- 验证：Python`py_compile`、JavaScript`node --check`和正式`index.html`重建均通过；板端`/usr/bin/sudo`、`/usr/bin/systemctl`存在且`sudo -n`可用。系统原有状态为degraded，与本功能无关，未修改已知失败服务。
- 状态：代码完成，下一步以干运行模式部署和接口/UI验收。
