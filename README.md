# RDK X5 ROS 自主导航车平台

> 面向四驱远程车的多端开源工程集合：STM32 底盘固件、ESP32-C3 网关、Android 掌机控制 APP、Wi‑Fi 摄像头模块，以及 RDK X5 ROS 自主导航控制台。

## 我的职责与开发流程

| 层级 | 我完成的工作 | 能力体现 |
|---|---|---|
| 底盘执行层 | 整理 STM32F103 四驱控制、控制帧、遥测、雷达与超时停车链路 | 嵌入式控制、串口协议、安全状态机 |
| 无线网关层 | 使用 ESP32-C3 完成 MQTT 接入、命令校验、UART 桥接和状态回执 | IoT 网络、弱网重连、跨 MCU 通信 |
| 人机交互层 | 开发 Retroid Android 横屏控制台、实体摇杆、遥测、急停、图传与工具页 | Android Compose、设备适配、交互安全 |
| 自主导航层 | 集成 RDK X5、ROS 2、雷达、SLAM、Nav2 与 Web 控制入口 | ROS 系统集成、导航链路、跨栈联调 |
| 工程交付 | 建立模块化目录、构建验证、敏感配置隔离、README/CHANGELOG 与版本标签 | 系统工程、验证闭环、可维护交付 |

```text
车辆需求与安全边界
  → STM32 底盘协议/遥测
  → ESP32-C3 MQTT-UART 网关
  → Android 手动控制与状态回显
  → RDK X5 ROS 2 感知、建图、定位与 Nav2
  → 分层构建 + 联调验证 + 文档版本发布
```

## 项目简介

本仓库把远程车开发过程中可复现的源代码统一管理，覆盖从底层执行机构、无线桥接、掌机人机界面到 RDK X5 ROS 导航链路的完整软件栈。STM32 和 ESP32-C3 工程保留历史迭代目录，便于追溯协议、驱动和控制策略的演进；Android APP 与 ROS Web Console 则作为当前上层控制入口。

## 功能特性

- 🚗 STM32F103 四驱电机、编码器、蓝牙、LD‑14 避障、WS2812 与 ICM42670 姿态采集。
- 📡 ESP32‑C3 MQTT 接入、UART4/UART5 桥接、遥测和语音串口通道。
- 🎮 Android 横屏掌机控制：登录、实体按键/摇杆、模式切换、遥测、语音提示和车辆控制。
- 📷 Wi‑Fi 摄像头、舵机云台和 AI 视觉案例代码。
- 🤖 RDK X5 ROS 2：LD‑14 驱动、底盘网关、地图/导航工具、仿真与 Web 控制台。
- 🧪 工程内保留已验证的编译、烧录、协议联调和交付记忆，便于后续迭代。

## 构建与验证

各子工程的详细命令以对应目录中的 README、脚本和工程文件为准。常用入口如下：

```text
Android：apps/beebot-android/  （Gradle / Android Studio）
STM32： firmware/stm32/        （Keil MDK / ARM 编译工具链）
ESP32： firmware/esp32c3/      （Arduino-ESP32 / PlatformIO）
ROS：   ros/bee-ros-web-console/（ROS 2 Humble / Python / 前端静态资源）
```

⚠️ 真车调试前必须先断开电机或架空车轮验证；车端应保留控制超时停车、断线安全状态和硬件急停。

## 安全与提交范围

仓库只提交源码、工程配置、必要脚本和可公开的开发文档。`.env`、账号密码、私钥、APK/固件产物、镜像、安装包、厂商资料和本地构建缓存均由 `.gitignore` 排除。连接参数请复制对应的 `.env.example` 到本地后填写，不要把真实凭据提交到 Git。

### 本地敏感配置

Android 本地登录参数使用外部 MQTT 环境文件中的 `LOCAL_LOGIN_ACCOUNT` 与 `LOCAL_LOGIN_PASSWORD` 注入；缺少配置时登录安全失败。真实 MQTT、萤石、签名和登录凭据均不得提交。
