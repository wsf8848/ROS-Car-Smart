# ESP32-C3 短周期 IP 证书与旧 TLS 栈兼容

## 现象

- WiFi 和 NTP 正常，Broker TCP 端口可达。
- 固件先偶发握手 socket abort，随后稳定报告服务器叶证书 pin 不匹配，车辆无法上线。

## 失败方案与证据

- 只替换新叶证书指纹：当前证书只有约一周有效期，下次自动续期必然再次断线。
- 直接 `setCACert(ISRG Root X2)`：实板返回 Mbed TLS `-9984`。
- 改用当前链中的 Root YE 作为 `setCACert()` 信任锚仍返回 `-9984`。
- 服务器实际发送完整四层链，排除缺失中间证书。Mbed TLS 2.28 API 文档明确其内置名称校验只支持 DNS；服务器证书 Subject 为空，唯一身份是 IPv4 SAN `43.138.223.90`，因此链正确仍在名称校验阶段失败。

## 最终修复

- 不再固定短期叶证书。
- 在 TLS 加密握手后、MQTT 认证前，以 Root YE 为信任锚调用 `mbedtls_x509_crt_verify(..., cn=null)` 校验证书签名链和有效期。
- 遍历叶证书 Subject Alternative Name 的 ASN.1 项，只接受 tag 7、长度 4 且值逐字节等于目标 Broker IPv4 的条目。
- 只有链、时间和 IP SAN 全部通过，才允许 PubSubClient 发送 MQTT 用户名和密码；失败时立即断开并记录 `credentials not sent`。

## 验证结论

- Arduino-ESP32 2.0.17 / Mbed TLS 2.28.7 编译通过并烧录 ESP32-C3 rev 0.4。
- 串口确认链、有效期与端点身份验证通过，MQTT 订阅和状态发布成功。
- 非运动安全停车帧完成 Broker -> ESP32 -> UART TX -> 状态回执闭环。
- 可复用判据：旧栈遇到只有 IP SAN、没有 DNS SAN/CN 的合法证书时，应区分“链验证”和“端点身份验证”；不可用永久 `setInsecure()` 或短期叶证书 pin 冒充可持续修复。
