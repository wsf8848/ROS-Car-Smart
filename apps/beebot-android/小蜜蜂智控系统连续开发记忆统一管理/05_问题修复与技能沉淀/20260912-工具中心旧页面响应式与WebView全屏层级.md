# 工具中心旧页面响应式与 WebView 全屏层级

## 现象

v2 将旧页面放入 132dp 左侧导航后的内容区，实际可用宽度减少。智能小车单行顶栏被挤成超高区域、急停逐字竖排；摄像头操作被挤出；设置底部不在首屏；ROS 网页触发旧响应式断点后堆成长单列。ROS 摄像头全屏还出现上黑下灰、退出按钮被 WebView 盖住。

## 根因

1. 旧 Compose 页面按 1334px 全宽设计，固定宽度和单行 Row 没有适配约 1060px 的新内容区。
2. WebView CSS viewport 在不同 ROM/缩放下不稳定，只靠媒体断点不能稳定区分工具页嵌入模式。
3. AndroidView/WebView 可能覆盖同一 Compose 绘制层；普通 `zIndex` 能保留点击树，但不一定让按钮真正绘制在 WebView 上方。
4. 网页全屏切类时保留滚动偏移，WebView 未覆盖部分会露出原生容器底色。

## 已验证解决方法

- 长控制条拆为明确双行，关键按钮 `maxLines=1`，URL 等长输入框使用 `weight(1f)`。
- 设置在掌机横屏采用左右双栏，每栏保留独立滚动作为更低高度兜底。
- ROS URL 增加 `embed=1`，网页用明确类应用紧凑尺寸；媒体断点只做额外响应式兜底。
- 全屏时归零网页滚动，网页、WebView 与 Compose 容器同时使用黑底。
- WebView 之上的关键退出操作用独立 Compose `Popup`；网页内再绘制无事件退出提示作为视觉兼容层。

## 验证证据

- 修复前：`build-evidence/ui-audit-v2.0.1-before/`。
- 修复后：`build-evidence/ui-audit-v2.0.1-after/`。
- 六个普通页面以及 ROS/摄像头全屏均逐张截图检查；退出全屏真实点击返回；无本应用 FATAL。
