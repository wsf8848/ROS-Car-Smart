# 2026-09-17 离线关键词语音助手第一版

## 任务目标

- 在现有 Paraformer 离线中英识别、CAM++ 声纹和 Android TTS 基础上，新增完全不依赖大模型的语音问答。
- 通过关键词/同义词匹配确定意图，只读取本机和 APP 的真实状态后回答；数据不存在或超时必须明确说明，不得编造。
- 第一版优先支持掌机电量、充电状态、电池温度、时间日期、网络、APP 版本，以及已有可靠数据源的车辆状态查询。
- 对话页逐轮显示“说话人问题”和“小蜜蜂助手回答”，TTS 播报期间避免被 ASR 再次识别形成自问自答。
- 完成单元测试、Release 构建、签名、覆盖安装和 Retroid 真机验证，并把检查点即时回写到本文件。

## 已确认方案

- 用户于 2026-09-17 明确要求开始执行第一版，并确认最终不接入大模型，只采用关键词意图和真实状态回答。
- 处理链路：Paraformer 最终句子 -> 本地意图解析 -> 真实数据提供器 -> 确定性回答 -> Android TTS -> 对话历史。
- 掌机电量使用 Android `BatteryManager` / `ACTION_BATTERY_CHANGED`；车辆状态只使用已有 MQTT/遥测新鲜度证据。
- 未命中意图时提示当前支持的问题，不转发网络服务。

## 真机问题：离开语音页后录音被再次拉起

- 发现时间：2026-09-17 17:40（Asia/Shanghai）；状态：修复中。
- 现象：语音助手页面实际布局、模型/声纹就绪和问答均正常；返回主控台后，`dumpsys audio` 仍反复出现本包 16kHz `VOICE_RECOGNITION` 的 `rec update/rec stop`，且一度显示 `active? true`。
- 已排除：不是本应用崩溃，PID 持续存在且 AndroidRuntime/libc 无 FATAL；也不是一次性退出动画延迟，等待超过 8 秒后仍有新录音会话。
- 证据支持的根因：工具层使用 `AnimatedVisibility` 保留退出动画内容，现有语音页只在 Compose `onDispose` 时停录；TTS 完成/识别循环可能在销毁前再次启动录音，因此“页面不可见”和“资源销毁”不是同一时刻。
- 修复方向：工具页关闭和从语音标签切走时显式调用会话 `detach()`，Activity 进入后台时再强制 `pause()` 与停止声纹登记；`onDispose` 继续作为最后兜底。
- 下一步：实施修复、重新构建安装，并以 `dumpsys audio` 的 stop 且无后续 update 复验。
