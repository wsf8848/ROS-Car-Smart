# 2026-09-17 ESP32-C3 服务器 TLS 证书续期修复

## 任务目标

- 定位 ESP32-C3 已连接 WiFi、NTP 正常，但无法连接 `43.138.223.90:8883` 的原因。
- 在不降低服务器身份校验、不泄露 MQTT 凭据的前提下修复，并完成编译、烧录和串口联网验证。
- 保留车辆上电停车、断线停车、控制帧校验和 UART4 协议等既有安全行为。

## 工作区保护边界

- ESP32-C3 工程不是独立 Git 仓库；本轮仅增量修改 TLS 连接实现、联调报告和相关连续开发记忆。
- MQTT 用户名、密码和 WiFi 密码继续只从外部 env 注入，不写入源码、日志或记忆。

## 检查点 1：故障分层与根因确认

- 状态：已完成（2026-09-17，Asia/Shanghai）。
- WiFi 已连接、NTP 时间正确；本机 `Test-NetConnection 43.138.223.90 -Port 8883` 成功，排除 WiFi、DNS和 Broker TCP 端口整体不可达。
- 服务器当前叶证书生效时间为 2026-09-15，失效时间为 2026-09-21；SHA-256 为 `C22486B379BD98A2A2B8AD676518DA32F29856F328A4790BCFA409B5424FFB6F`。
- 固件仍固定旧叶证书 SHA-256 `4FA4E82DD52A56D9B07778A7B2FF8923F87FAA93CF296AC132F444350243A4EB`，与串口 `server certificate pin mismatch` 完全吻合。
- 服务器证书链为叶证书 -> Let's Encrypt YE2 -> Root YE -> ISRG Root X2；叶证书 SAN 明确包含 IP `43.138.223.90`，本机系统信任链与 IP 身份验证通过。
- 日志前几次 `ERROR - Generic error` / `errno 113` 属于握手阶段的瞬时网络中止；随后稳定握手并报 pin mismatch，最终阻塞原因是旧叶证书固定值。
- 仅替换为新叶证书指纹只能维持到下一次短周期续期，不是可持续修复。
- 下一步：内置长期根 CA，恢复 TLS 链、有效期和 IP 身份验证；编译后再烧录实板验证。

## 检查点 2：初版 CA 修复、失败证据与旧栈边界

- 状态：已完成并被检查点 3 的最终方案取代（2026-09-17，Asia/Shanghai）。
- 第一版移除旧叶证书 SHA-256，尝试直接 `setCACert(ISRG Root X2)`；编译成功，但实板返回 Mbed TLS `-9984`。
- 第二版将信任锚下移到链中的 Root YE，仍返回 `-9984`，证明不是顶层根证书算法导致。
- Python/OpenSSL 运行时检查确认服务器实际发送 4 张完整证书，排除中间证书缺失。
- 证据根因：Arduino-ESP32 2.0.17 所带 Mbed TLS 2.28.7 文档明确内置名称校验只支持 DNS；当前叶证书 Subject 为空，只有 IPv4 SAN，所以链正确仍被名称检查拒绝。
- 失败期间固件从未发送 MQTT 凭据；所有错误路径均显示 `credentials not sent`。
- 下一步：保留旧栈，在加密握手后、认证前分离执行链/时间验证和 IPv4 SAN 校验。

## 检查点 3：最终修复、烧录与公网闭环

- 状态：已完成（2026-09-17，Asia/Shanghai）。
- 最终实现不再固定短期叶证书：加密握手后以 Root YE 校验叶证书 -> YE2 -> Root YE 的签名链和有效期，再解析叶证书 SAN，要求 IPv4 地址逐字节等于 `43.138.223.90`。
- 只有链、时间和 IP SAN 全部通过才调用 `PubSubClient.connect()`；任一失败立即断开，账号密码不发送。
- 编译成功：Arduino-ESP32 2.0.17 / Mbed TLS 2.28.7；RAM 40,460 / 327,680（12.3%），Flash 897,908 / 1,310,720（68.5%）。
- 端口枚举只有 `USB VID_303A&PID_1001` 的 COM8；烧录识别 ESP32-C3 QFN32 rev 0.4、4MB XMC Flash，全部写入段 `Hash of data verified` 并硬复位。
- 串口证据：`certificate chain, validity, and endpoint identity verified`，随后 `MQTT connected; control_subscribe=OK, status_publish=OK`。
- 第一次安全停车探针恰逢关闭串口监视器触发 USB 复位，先读取旧 retained 在线状态并在重新订阅前发帧，因此 `ACK_TIMEOUT`；这是测试时序失败，不是业务回归。
- 板子稳定后同一探针复测通过：`seq=146 / 0x49`，回执 `control_rx=1`、`last_seq=146`、`last_cmd=73`，`RESULT=SAFE_STOP_ACK_PASS`。
- 新固件 SHA-256：`firmware.bin 3DFFF0D46A2F006BCE6865900127308D683CF1997337845BA0E4D77C8D051975`；bootloader 和 partitions 哈希未变。
- 未验证边界：本轮只发送安全停车命令，没有发送方向运动帧；既有 300ms 运动失联停车逻辑未改动。
- 结论：用户报告的证书续期断线已修复，正常短周期叶证书续期不再需要更新固件；启动阶段偶发 socket abort 由退避重试自动恢复。
