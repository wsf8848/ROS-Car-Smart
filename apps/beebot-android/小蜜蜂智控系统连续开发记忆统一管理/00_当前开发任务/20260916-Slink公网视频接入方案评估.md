# 2026-09-16 Slink 公网视频接入方案评估

## 任务目标

- 评估新购 Slink IPC 摄像头通过车载 WiFi 接入公网并在 App 主页面显示实时视频的可行性。
- 对比 RTMP 中继、RTSP 直拉、HTTP-FLV/HLS 与 WebRTC 的稳定性、时延和 Android 端实现成本。
- 只读核验现有 App、公开协议文档和服务器能力；本轮不修改 App 代码、不部署服务、不发布 OTA。

## 检查点 1：工程与现有视频能力审计

- 状态：已完成（2026-09-16）。
- 当前工作区包含历史未提交改动，必须继续增量开发，禁止覆盖或回退。
- 当前 App 为 v2.3.2/versionCode 31 的进行中代码状态；主页面 `DashboardCameraBackground()` 使用 WebView 直接加载保存的摄像头 URL。
- 工具中心 `CameraStreamScreen` 使用 WebView 播放 HTTP/MJPEG/JPEG，RTSP 则依赖系统 `VideoView`。
- 结论：现有实现适合局域网临时预览，不适合公网低延迟、弱网重连、首帧统计和稳定解码；正式方案需要独立原生播放器与视频链路状态机。

## 检查点 2：Slink 协议文档审计

- 状态：已完成（2026-09-16）。
- Eolink 公共项目可访问，显示 229 条 IPC HTTP API，分组包含基础 API、录像、WiFi P2P、P2P IoT、平台管理、报警、图像、云台等。
- 商品信息明确标注 ONVIF、RTSP、RTMP，但公开文档列表本身尚未证明具体主/子码流 URL、鉴权格式、H.264/H.265 编码、RTMP 主动推流配置入口或断线重推行为。
- 在拿到摄像头实物、局域网 IP、管理账号和卖家给出的码流/推流参数前，不编造 URL 或私有协议字段。

## 检查点 3：服务器只读核验

- 状态：已完成（2026-09-16）。
- 按 Cloud_OTA 已验证路径使用本机专用 SSH 密钥，只读取服务状态、监听端口、Nginx 配置和资源，不读取或记录私钥正文。
- 服务器为 4 核、约 3.6 GiB 内存，当前可用约 2.5 GiB；系统盘 40 GiB，剩余约 16 GiB；负载约 0.01。
- 当前运行 Nginx、Mosquitto 和多个授权/OTA 服务；未发现 SRS、FFmpeg 或其他视频媒体服务。
- 服务器内部没有 1935、1985、8080 监听进程。公网对这些端口的 TCP 可达和 HTTP 502 只是上游网关行为，不能视为流媒体服务可用。
- 结论：资源足够先承载单路“不转码”中继，但视频必须部署为独立目录、独立 systemd 服务和独立 Nginx 路由，禁止改动现有 OTA/MQTT 实例。

## 推荐架构

```text
Slink IPC（车载 WiFi，可访问互联网）
  -> RTMP 主动推流，H.264 主码流/子码流
  -> 腾讯云独立 SRS 实例（只转封装，不转码）
  -> WebRTC/WHEP 低延迟播放（主方案）
  -> HLS 兼容回退（只作保底，不用于遥控第一视角）
  -> Android 原生 WebRTC 客户端嵌入 VehicleDashboardScreen
```

- 推荐 RTMP 只作为摄像头到服务器的上行协议，不作为 App 最终播放协议。
- App 到服务器优先 WebRTC/WHEP，目标正常网络端到端时延约 0.3 至 1 秒；HLS 常见数秒，不适合驾驶操作。
- WebRTC 主链路使用原生 WebRTC SDK；Media3 只负责 RTSP/HLS 兼容回退，不能把 Media3 当作 WebRTC 播放器。
- 若该摄像头只能提供局域网 RTSP、不能主动 RTMP 推流，则需要车端增加常在线网关设备拉取 RTSP 再推公网；ESP32-C3 不能承担视频转发。
- 视频链路与 MQTT 控制链路必须隔离：视频断流只提示并重连，不能阻塞停车、上锁或摇杆控制。

## 参数建议与容量边界

- 第一阶段优先 H.264、1280x720、20 至 25 fps、1.2 至 2.0 Mbps、关键帧间隔 1 秒、关闭 B 帧；网络稳定后再评估 1080p 2 至 4 Mbps。
- 服务器只做转封装时，单路视频资源压力可控；现有 16 GiB 磁盘余量不适合长期录像，第一阶段禁用服务端录像。
- 若启用 H.265，需先验证 Retroid Pocket 4 硬解和 WebRTC 兼容性；为降低首版风险，优先 H.264。
- 必须加随机流密钥、播放鉴权、推流覆盖保护和 TLS；不得使用可猜测的固定公开播放 URL。

4. 依次验证：本地测试流、服务器推拉流、Retroid 真机解码、弱网恢复、连续运行、视频断流时控制链路独立可用。
