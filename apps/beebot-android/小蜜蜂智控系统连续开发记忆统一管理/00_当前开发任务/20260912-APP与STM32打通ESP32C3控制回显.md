# 2026-09-12 APP 与 STM32 打通 ESP32-C3 控制回显

## 任务目标

依据已烧录 ESP32-C3 工程的实际代码，完善 Android APP 的 20 字节 MQTT 控制发布、22 字节遥测解析与状态回显，并补齐 STM32 UART4 控制命令消费，使 Retroid -> MQTT -> ESP32-C3 -> UART4 -> STM32 控制链路和反向遥测回显具备完整代码基础，随后分层编译、装机和硬件验证。

## 工作区保护与检查点 1：基线审计

- 时间：2026-09-12（Asia/Shanghai）。
- 状态：完成。
- APP 基线为 v2.0.1 / versionCode 26；仓库已有大量历史未提交与未跟踪改动，本轮只在现状上增量开发，不回退、不清理用户内容。
- ESP32 实际控制格式已从 `src/main.cpp` 复核：`55 43 01 seq cmd 00...00 CRC8 5B`，CRC-8/ATM 多项式 `0x07` 覆盖 0~17，Payload 必须为原始 20 字节、QoS 0、Retain false。
- ESP32 命令白名单为 `41~49`、`5B~5D`、`6A~6B`；重复/旧序号、CRC/长度/保留区错误均拒绝，运动命令需在 300ms 内持续刷新。
- ESP32 遥测为 `0x51(9B) + 0x53(5B) + 0x52(8B)` 三类原始帧的最新值拼接，最长 22 字节；APP 现有 `SmartCarTelemetry.feedRx()` 已支持连续分帧。
- APP 当前只订阅状态/遥测，未发布控制帧；主控台停车和模式按钮也未实际发送，实体摇杆没有 MQTT 连续控制循环。
- STM32 1-13 当前只建立 UART4 RX 中断/环形缓冲，主循环尚未消费，因此只改 APP 无法使车轮动作。
- 解锁、上锁、鸣笛仍无车端命令证据，继续安全阻断，不编造协议。
- 未验证边界：本检查点只完成代码与协议审计，尚未编译、装机、测 MQTT 或架空车轮。
- 下一步：实现可测试的 Android 控制帧编码与 MQTT 发布/状态回执，再接主控台实体输入和动作入口。

- 状态：代码完成，待单测和构建验证。

- 新增协议单测：序号 66、停车 `0x49` 必须生成已通过公网探针验证的 CRC `0xDA`；另覆盖八方向与死区停车映射。
- `RemoteVehicleRepository` 新增 QoS0、Retain false 的同步发布入口、递增/回绕序号，以及 ESP32 JSON 状态中的 `last_seq/last_cmd/control_rx/control_errors/uart_frames/uart_errors` 解析。
- APP 业务 RTT 改为以本机控制帧发布时间到 ESP32 `last_seq` 回执时间计算，不再依赖不存在的服务端字段。
- 主控台新增 50ms 控制循环：左 Y + 右 X 映射八方向；回中、A 键、打开工具中心均下发停车；L2/R2 每 250ms 下发 `0x6A/0x6B`。

- 修复底盘 `0x52` 遥测的 int8 二补码解析；HUD 将单位从未经证实的 m/s 改为真实的十毫秒编码器脉冲，并优先用车端 `carStatus` 回显控制模式。
