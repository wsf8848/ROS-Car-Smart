## 推荐阅读顺序

1. 先读本索引和 `01_项目主线与版本/当前项目基线_20260805.md`。
2. 按任务进入对应分类，至少读取该分类最新一份记忆。
3. 涉及协议或 Bug 时，再读 `05_Bug修复与技能沉淀`，避免恢复已被取代的实现。
4. 开发结束后新增/更新本轮记忆，并同步更新本索引的清单、状态和下一入口。

## 统一管理规则

1. 本目录是唯一正本；后续不得向 `.codex/memories` 或其他 `docs/` 目录散放新的本项目连续开发记忆。
2. 每轮开发新建一份记忆，按顺序记录需求确认、检查、实现、编译、装机、页面验证、硬件验证和遗留项；未完成步骤也要写明原因。
3. 每完成一个可验证步骤就更新本轮记忆；整轮验证完成后补齐最终结果，并同步本索引。
4. “编译成功”“APK 安装成功”“字节已调用发送”不等于真实小车动作成功；没有实车、日志或抓包证据时必须写“待硬件验证”。
5. 每次 Bug 修复完成后，同时把可复用的根因与修复规则补充进 `smart-car-page-development` Skill。
6. 历史失败记录不得删除，但必须标记“已取代/失败”，并指向当前正确结论。
