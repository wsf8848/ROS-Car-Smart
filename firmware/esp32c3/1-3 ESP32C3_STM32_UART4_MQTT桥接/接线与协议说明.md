# ESP32-C3、STM32 UART4 与 MQTT 桥接说明

## 接线

| STM32F103RC | ESP32-C3 Super Mini | 方向 |
| --- | --- | --- |
| PC10 / UART4_TX | GPIO20 / RX | STM32 遥测 → ESP32 |
| PC11 / UART4_RX | GPIO21 / TX | ESP32 控制 → STM32 |
| GND | GND | 必须共地 |

两侧都是 3.3V TTL，参数 `115200-8-N-1`、无流控。不要连接 5V TTL 或 RS-232 电平。ESP32 板载 LED 继续使用 GPIO8。

## MQTT 控制帧

控制主题 Payload 固定 20 字节：

| 字节 | 含义 |
| ---: | --- |
| 0 | `0x55` 帧头 |
| 1 | `0x43` 控制帧类型 |
| 2 | `0x01` 协议版本 |
| 3 | 递增序号，允许 255 → 0 回绕 |
| 4 | STM32 单字节命令 |
| 5～17 | 保留，当前必须全为 0 |
| 18 | CRC-8/ATM，多项式 `0x07`，覆盖字节 0～17 |
| 19 | `0x5B` 包尾 |

允许命令：`0x41～0x48` 八方向、`0x49` 停车、`0x5B/0x5C/0x5D` 手动/避障/自主、`0x6A/0x6B` 减速/加速。其他命令、重复/旧序号、错误 CRC、错误长度或保留区非零都会被拒绝。车辆运动期间发生非法帧、Wi-Fi/MQTT 断线或连续 300 ms 未收到新方向帧，ESP32 会发送三次 `0x49`。

## MQTT 遥测

ESP32 非阻塞解析 STM32 的三种原始帧：

- `55 51 ... 5B`：9 字节雷达/车辆状态。
- `55 53 ... 5B`：5 字节电池状态。
- `55 52 ... 5B`：8 字节底盘状态。

ESP32 缓存三种最新帧并按 20 Hz 合并发布，完整 Payload 为 22 字节且顺序为 `0x51 + 0x53 + 0x52`。掌机现有 `SmartCarTelemetry.feedRx()` 支持在一个 MQTT Payload 中连续解析多帧。

## 当前 STM32 边界

`1-13 UART4接入ESP32C3遥测` 已经将遥测复制到 UART4，也已建立 UART4 RX 中断和 64 字节环形缓冲，但主循环尚未调用 `Esp32Link_ReadByte()`。因此：

- 遥测上行逻辑已具备两端代码基础，接线后才能做电气实测。
- ESP32 能收到 MQTT 控制并向 PC11 发送命令。
- 现有 STM32 固件不会从 UART4 缓冲取出命令驱动车辆；后续必须在 STM32 主循环接入与 USART2 相同的白名单解析和 350 ms 停车保护。

在 STM32 适配和架空车轮验证完成前，不得把本工程描述为“已远程控车”。
