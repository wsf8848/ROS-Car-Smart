## 安全策略

- 上电立即向 STM32 发送三次 `0x49`。
- 只接受 20 字节正式封装和已确认的 STM32 命令白名单。
- 重复/旧序号、错误 CRC、错误保留区或未知命令均拒绝。
- 运动后 300 ms 无新方向帧，发送三次 `0x49`。
- 运动期间 Wi-Fi/MQTT 断开或收到非法控制帧，发送三次 `0x49`。
- 控制消息 QoS 0、Retain false，避免重连执行历史动作。
- `0x5E/0x5F` 分别开启/关闭 STM32 连续双响；ESP32 跟踪鸣笛状态，Wi-Fi/MQTT 断开或非法控制时主动关闭。
- 当前固件在发送 MQTT 账号密码前，以 Root YE 信任锚校验证书链和有效期，并显式校验叶证书 IPv4 SAN 必须等于 `43.138.223.90`；服务器正常续期无需再更新叶证书指纹。

## 2026-09-12 WiFi 远程控制故障修复

### 现象与根因

- APP 已显示车辆在线和 WiFi 远程，但车轮无法持续动作。
- COM8 抓包显示每一帧 `0x41` 都被 MQTT 校验接受并发送给 STM32，随后立即出现 `motion control timeout exceeded 300 ms` 和 `0x49 x3`。
- 根因是 `loop()` 在 `mqttClient.loop()` 之前保存旧 `now`，而 MQTT 回调以稍后的 `millis()` 更新 `lastMotionControlMs`；同一轮的 `now - lastMotionControlMs` 发生 uint32 下溢，错误满足超时条件。

### 修复与实机证据

- 在处理 MQTT 回调后重新读取 `watchdogNow = millis()`，再执行 300ms 超时判断；Wi-Fi/MQTT 断线、非法帧和真实超时停车均保持不变。
- 修复固件已使用 PlatformIO/Arduino-ESP32 2.0.17 编译并烧录 COM8；ESP32-C3 rev 0.4、4MB XMC Flash，各写入段均 `Hash of data verified`。
- 正常前进期间连续 `0x41` 全部被接受，中间不再出现误超时停车。
- STM32 回传非零四轮包：`55 52 1C 1C 19 1A 00 5B`，证明 APP -> MQTT -> ESP32-C3 -> UART4 -> STM32 -> 四轮 -> UART4 -> ESP32-C3 -> MQTT -> APP 闭环有效。
- 强制停止 APP 后，最后一帧 `0x41` 位于 9.517s，安全停车位于 9.819s，实测约 302ms，并发送 `0x49 x3`。

## 2026-09-17 TLS 证书续期故障修复

### 现象与根因

- ESP32-C3 的 WiFi、NTP 和 TCP 8883 均正常，但反复报告 `server certificate pin mismatch; credentials not sent`。
- 服务器于 2026-09-15 换发短周期 Let's Encrypt IP 证书，叶证书 SHA-256 从固件中的旧值变为 `C22486B379BD98A2A2B8AD676518DA32F29856F328A4790BCFA409B5424FFB6F`。
- 仅替换叶证书指纹会在下一次续期再次失效。Arduino-ESP32 2.0.17 所带 Mbed TLS 2.28 又只支持内置 DNS 名称匹配，无法直接匹配此证书唯一的 IPv4 SAN。

### 修复与实机证据

- 移除会随续期失效的叶证书固定值。
- TLS 加密握手完成后、发送任何 MQTT 凭据前，显式调用 Mbed TLS 验证叶证书 -> YE2 -> Root YE 的签名链和有效期；Root YE 信任锚 SHA-256 为 `0FC0901CCA2BAE9E9FDBB02D50D02F1094F7B36672086991B9E897626DC485F0`，有效至 2032-09-03。
- 单独解析叶证书 SAN，要求 IPv4 地址逐字节等于固定 Broker IP `43.138.223.90`；链、时间或 IP 任一失败都会断开，且日志明确 `credentials not sent`。
- 编译成功：RAM 40,460 / 327,680（12.3%），Flash 897,908 / 1,310,720（68.5%）。
- COM8 烧录成功：ESP32-C3 rev 0.4、4MB XMC，bootloader、分区表和应用各段均 `Hash of data verified`，硬复位成功。
- 串口实测：`certificate chain, validity, and endpoint identity verified`，随后 `MQTT connected; control_subscribe=OK, status_publish=OK`。
- 安全停车探针复测：`seq=146 / command=0x49`，状态回执 `control_rx=1`、`last_seq=146`、`last_cmd=73`，结果 `SAFE_STOP_ACK_PASS`。
- 启动阶段仍偶见 `errno 113 Software caused connection abort`，指数退避后自动恢复；它与已修复的证书身份错误不同，不再阻止最终上线。
