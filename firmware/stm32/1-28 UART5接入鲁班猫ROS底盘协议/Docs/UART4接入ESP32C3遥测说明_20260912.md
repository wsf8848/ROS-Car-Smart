# UART4 接入 ESP32-C3 遥测说明

## 一、任务范围

本版本以 `1-12 自主导航调速修复` 为基线，保留 USART2 蓝牙收发功能，新增独立 UART4 与 ESP32-C3 通信。STM32 每次生成蓝牙遥测包后，将同一块字节数组依次发送到 USART2 和 UART4，保证两路数据内容、顺序和发送周期一致。

本阶段只完成车辆遥测复制。UART4 接收中断和 64 字节环形缓冲区已经就绪，但尚未把 ESP32-C3 下发字节接入车辆控制解析，避免未经协议校验的数据直接驱动车辆。

## 二、硬件连接

| STM32F103RC | ESP32-C3 | 说明 |
|---|---|---|
| PC10 / UART4_TX | RX | STM32 向 ESP32-C3 发送遥测 |
| PC11 / UART4_RX | TX | 为后续 ESP32-C3 下发控制预留 |
| GND | GND | 必须共地 |

两侧串口均使用 3.3V TTL 电平，参数为 `115200-8-N-1`，无硬件流控。禁止接入 RS-232 电平。

## 三、复制的数据包

| 类型 | 帧格式 | 长度 |
|---|---|---:|
| 雷达与车辆状态 | `55 51 前 后 左 右 雷达状态 车辆状态 5B` | 9 字节 |
| 电池状态 | `55 53 电压(0.1V) 百分比 5B` | 5 字节 |
| 底盘状态 | `55 52 左后 左前 右前 右后 陀螺仪 5B` | 8 字节 |

三个数据包沿用原掌机蓝牙二进制协议，不增加文本、换行符、MQTT 字段或额外包头。ESP32-C3 可按第二个包头 `0x51/0x52/0x53` 区分类型，并原样发布到后续约定的 MQTT 主题。

## 四、代码结构

- `Hardware/Esp32Link.c/.h`：UART4 初始化、阻塞式数组发送、接收中断、环形缓冲区和溢出统计。
- `Hardware/Bluetooth.c`：在三类原蓝牙数据包发送点增加 UART4 同包复制。
- `User/main.c`：系统初始化阶段调用 `Esp32Link_Init()`。
- `Project.uvprojx`：将 ESP32-C3 链路模块加入 Keil 工程 Hardware 分组。

## 五、后续控制接入约束

下一阶段应先确定 MQTT 下发帧格式、序号/校验、心跳和超时停车策略，再从 `Esp32Link_ReadByte()` 取字节并接入控制解析。UART4 中断只收字节，不应在中断内执行电机动作、MQTT 逻辑或复杂协议解析。

## 六、验证记录

2026-09-12 使用 Keil ARM Compiler 5.06 update 7 对 `Project.uvprojx` 执行全量重编译：

- 编译结果：`0 Error(s), 0 Warning(s)`。
- 程序占用：`Code=15982, RO-data=3138, RW-data=152, ZI-data=3984`。
- 输出文件：`Objects/Project.axf`、`Objects/Project.hex`。
- 静态检查：三处 USART2 遥测发送点均紧邻同长度、同数组的 UART4 复制发送，工程 XML 可正常解析。
- 硬件状态：本机检测到 Espressif USB 串口 `COM8`，但未检测到 J-Link/STM32 下载器。

因此，本次已完成代码与编译验证；尚未烧录 STM32，也未使用逻辑分析仪或 ESP32-C3 程序核对 UART4 实际字节流。接线后的验收应确认 PC10 每 10 ms 依次输出 `0x51`、`0x53`、`0x52` 三类数据包，并与 USART2 同周期数据逐字节一致。
